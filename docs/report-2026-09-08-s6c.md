# 阶段 D 接力：S6c 通知时序修订（2026-09-08）

本轮接续 `docs/report-2026-09-07-phase-d.md` 的 S6c 未收口项，修正真实模型主动复读后仍等待三个写者同时位于待投递队列的假设。确定性集成场景和 Cohere 的一次真实模型集成场景已通过；后者在后续自主开发阶段超时，**本轮没有完整真实链路成功记录**。

## 实现与验证边界

- `family-notice.ts` 在第一名分支写入后，先检查源线程和另一分支收到的家族折叠；第二名分支执行后，再检查其余两人的通知。每次匹配当前磁盘 SHA256、家族和实际写者，折叠的每个路径都须保留在原始前提中。
- `premises pending --json` 增加已有稳定字段 `noticeId`。场景检查写者之间不共用通知身份，并将前后队列与原始投递事件按写者及通知 ID 对齐；通知无记录消失仍会失败。
- 投递与修复分列。只有捕获待投递状态之后，同一写者复读同一路径的相同新版本，才计为已修复；只确认投递、读取旧版本、别人复读或仅修复部分路径均不会冒充全部修复。正常投递但未复读可以是场景结果，报告明确保留 `not-proven-repaired`。
- `live-run.ts` 在集成阶段通过后立即保存 `runs/live-integration.json`。后续开发或分叉失败时保留集成步骤及统计，整轮仍为 `ok: false`。独立子进程回归验证了这个失败路径，也检查错误脱敏与测试模块隔离。
- 原默认 `minimax/minimax-m3:free` 返回 404，当前模型目录只有其付费变体。Windows 入口改用本轮实际跑通集成阶段的 `cohere/north-mini-code:free`，保留 `E2E_LLM_MODEL` 覆盖入口。
- 模型请求共用调用方原有的整轮 50 秒预算，移除额外的单请求 25 秒提前截断。请求中止回归通过；本轮尚未证明这能解决 Cohere 的自主开发超时。S6c 的状态等待上限和六轮工具循环上限未提高。

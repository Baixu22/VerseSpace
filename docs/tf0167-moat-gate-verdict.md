# TF-0167 判决书：benchmark 闸门三项前置的收敛结论与有据关闭

- 日期：2026-09-13
- 判决人：柏旭授权，Helm 依 TF-0136 先例执行（提案式判决，本文件为权威记录）
- 对象：TF-0167（补齐 benchmark 闸门剩下的三项：B 的 git/human 写者、C 的人工封印复核、D 的比值带）
- 结论先行：**三项前置在当前现场结构性不可达，benchmark 闸门保持「有据的关闭」；对外的 stale-premise benchmark 不得写。TF-0167 以 deprecated 终态收尾，重启条件见 J3。**

## 一、事实（全部可复算）

### F1 · A 已达标且单调

校准表行数 57（2026-09-12 现场）→ 59（2026-09-13 复测），阈值 ≥50，单调可复现。A 不再是问题。

### F2 · B 的产生机制有结构性缺口（这不是「没跑够」）

代码事实：

1. `premise_stale` 全仓**唯一**追加点是 `src/runtime/premises.ts:410`（`reconcilePremises`）。
2. reconcile 只处理 `kind ∈ {agent, human}` 的写者（`premises.ts:327`），git/ci 写者被显式跳过——**「失效制造者是 git」这条信息在当前实现里不会进入 premise_stale 事件**。
3. 事件的 `payload.writer` 是**前提持有者**（被通知的写者），不是失效制造者。因此护城河 B 的口径（`gitOrHumanNotices`：payload.writer 回查注册表 kind）实义是「**human 或 git 作为前提持有者收到了失效通知**」。
4. human 写者的**读集**在产品里没有生产路径：watcher R1 只给 human 记写集（`src/watcher/index.ts:100-107`，`used: []` 恒空）；读集只来自 agent 会话的 `recordActivity(used)`。唯一的外部入口 `sessions record --used`（TF-0150）在无编辑器集成的现场无人调用。
5. 现场 232 个写者全部 `kind=agent`（2026-09-13 清点）。

推论：B=0 是当前产品形态的**结构性结果**。它要的不是一次实验，是「human 读集的产品级生产路径」（如编辑器集成）。

### F3 · C 缺的是真实使用者，不是复核工具

`seal.reviewed` 强制 `source: "human"`（`src/runtime/seal-review.ts:20`），且必须指向一条 `seal.decided: block`。现场 165 条 block 全部来自脚本编排的模型线程（soak 形态），无真人复核者 → `seal.reviews.correct` 恒 0。复核 CLI（`premises review-seal`）已就绪，缺的只是**人**。

### F4 · D 的定量判定：负载形状，不是噪声也不是口径错误（2026-09-13）

- 全部 80 次 premise_pass 集中在 2026-09-12 09:50–12:32（2.7 小时 soak 批次）。
- 聚合 notifiedRatio = 0.3149（与 ledger 报告的 0.315 精确一致）。
- 轨迹：第 1 轮 1.0（dedup 库存为零）→ 快速收敛 → 自第 21 轮起稳态在 0.30–0.33 窄幅波动，曾触及带内 0.2978（第 73 轮）。
- 恒等式精确闭合：overlaps 9766 = dedup 6691 + notified 3075（L1/L2/L3 全零）。
- 判定：**soak 形态每轮产生全新 (writer, path, version) 组合，dedup 只能抑制重复失效、无法抑制新组合** → notified 占比结构性偏高。这不是采样噪声（轨迹平稳收敛，非抖动），也不是口径错误（band 语义正确：高于带=通知吵到写者学会忽略；低于带=谓词在吞真实失效）。与 `premise-counts.ts:193-198` 记录的下侧漂移（租户实测 0.16→0.058，空闲数小时）是**同一机制的两个方向**。
- 处置：band（10–30%）**不动**，口径不改，阈值不调。真实使用窗口（写者与失效重复出现的自然使用）才会把比值拉回带内——届时复核。

### F5 · 受控实验路线被否

验收① 曾设想「受控的真实 git 提交（或人写）」。复核后否决：AI 编排的读活动若记为 `kind=human` 即**冒充写者身份**（验收①自设红线，也是账本纪律「无真实使用保持 unknown」的核心）；且该实验对工程无增益——正确结论（B 缺产品路径、C 缺真人、D 缺真实窗口）不靠补数据得出，靠判定得出。向使用者索要「真人数据」本身是对前置性质的误判。

## 二、判决

- **J1（闸门）**：benchmark 闸门保持关闭。这不是未完成，是**有据的关闭**：B 缺 human 读集的产品路径，C 缺真实使用者，D 缺真实使用窗口。对外的 stale-premise benchmark 不得写。
- **J2（节点终态）**：TF-0167 的 purpose——「把 benchmark 可对外写收敛成明确前置、每个前置知道该由谁做」——已达成。答案为「不是本现场能补的」。节点以 **deprecated** 终态收尾（CLI 无删除动作，deprecate 是唯一出口，与 TF-0132/TF-0146 先例一致），保留审计痕迹。
- **J3（重启条件，三者同时满足才重启）**：
  1. human 读集有产品级生产路径（如编辑器集成把真实的人读记为 used）；
  2. 存在真实使用者参与封印复核（seal.reviewed 的 source=human 有真人背书）；
  3. 真实使用窗口（非 soak 形态）的 premise_pass 积累，D 的带内/带外可按自然负载复核。
  重启时**新开节点**，不复活本节点。
- **J4（判据）**：一律不动。不降阈值、不改 band、不放宽 C 的人工要求。`benchmarkGate` 的四条件 AND 保持权威。
- **J5（遗留）**：A=59 的读数随真实使用继续单调增长即可，无需照看。现场 `live-moyu-moyu-soak` 保留为 F2/F4 的证据现场，不再追加写入。

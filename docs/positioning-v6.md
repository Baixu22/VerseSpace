# Workbench 定位 v6：交互层 —— 对话是输入面，执行是结构的来源

- 状态：调研与历史设计；现行工程边界由 [ADR-0010](./decisions/0010-premise-custody.md) 收敛
- 日期：2026-08-30
- 关系：**不取代 [`positioning-v5.md`](./positioning-v5.md)，是补上它缺的那一层。** v5 定了运行时（协调），v6 定交互。两者共用同一条原则：**结构从观测中长出来，不由用户声明。**
- 依据：六路独立深度调研（渐进形式化的成败 / 非线性 LLM 界面实测 / 混合主动与提议阈值 / 活动式计算与恢复 / 追溯式结构化 / grounding 与承诺理论）。证据分级见 §10。

---

**现行交互：默认线性对话，恢复时先看有来源的仓库事实。** 分叉不增加前置步骤；不建树导航、对话结构识别器或询问式提议 UI。L3 与 TF-0100/0101 等待 TF-0136 的真实两周证据门；下文候选方案不代表已经开工。

## 0. 问题陈述（用户原话）

> "对话本身是必要的，抛弃对话像 Coze、Dify 那样的纯粹 DAG 也不好，因为会加剧交互成本。**因为对话的质量是参差不齐的，这是最关键的**——我的一个随口的任务需要手动去选择一个图或者工作流都不是很好。但也没有什么好的理念能够将那些交互方案进行总和。"

## 1. 这个直觉是对的，而且 1993 年就被证明是对的

Shipman & Marshall《Formality Considered Harmful》（CSCW 8:333–352, 1999）列了用户拒绝结构的四个原因，与上述陈述逐条对应：

| 文献分类 | 对应 |
| --- | --- |
| **认知开销**："分块、链接、命名带来大量额外决策" | "衍生出来需要额外成本" |
| **默会知识**：设计学生**无法**产出 IBIS 论证，尽管录像显示讨论本就是那个形状 | 事后能分析 ≠ 当场能生成 |
| **过早结构**：Malone 1983 —— "不填它们意味着我现在可以推迟决定" | "随口的任务不该先选工作流" |
| **情境结构**："不同情境需要不同的形式化结构" | **"对话的质量是参差不齐的"** |

两句原文是本文档的基石：

> "我们希望揭穿一条**危险地诱人的推理**：只要你为嵌入式表示造出对的界面，用户就会去形式化他们任务域中你想要的那个方面。"

> "无法处理形式化流程之例外的系统，无法支持那大量需要例外流程的情形……**几乎所有办公流程最后都是规定形式的例外**（Suchman 87）。"

第一句否掉"把 DAG 编辑器做得更好用"；第二句是对 Coze/Dify 的判决，提前 25 年写就。

## 2. 但那条文献的药方是一片墓地

诊断成立，**药方（先随意捕获、让系统事后识别结构）在 35 年里从未上线**，而且反证由其作者自己发表：

- **VKB**（旗舰系统）："由于人们很少回头把信息空间弄一致，这会导致后期无法解释或误解。" 他们做重放**正是因为用户从不清理**。纵向 N=2；学生"推迟结构化直到理解更多"，**然后再没有过**。作者自陈假说：短期研究里的视觉规律性可能是**新奇效应**，"随时间磨掉"——**若如此，解析器赖以生存的信号是研究假象。**
- **Aquanet（2 年）**：形式化最终发生了，但**缓慢、冗余、不一致**（同一区分被编码成三种方式"且并不总是一致"）。
- **IBIS 的成功"依赖严厉的社会压力、大量培训或持续的人工引导"——起作用的是一个人，不是工具。**
- **PIM 外部证据**：书签研究（N=50，250 目标）——**16% 经书签找回，仅 4% 经书签层级**，其余来自**永远可见**的书签栏（**可见性有效，层级无效**）；信息碎片研究（533 个）被试原话"**我很想有时间整理，但这从来没发生过**"；N=345、8.5 万次找回动作研究：**预先归档"低效且不改善找回成功率"**；**GTD 每周回顾零实证支持**（其奠基论文自陈"目前还没有实证研究证实这些主张"）。
- **现代记录**：识别器只在实验室造过一次。**Tinderbox 主动移除了它；Obsidian Canvas 规格层面惰性**（仅 `id,x,y,width,height,color`）；**Ink & Switch 三次尝试并发表原因**——Inkbase："识别错误……让用户感到无力和困惑。**我们总体上怀疑这件事能否做到可靠。**" 商业上 Muse 峰值约 $120k ARR 后关停、Kosmik 2026-05 日落，**而活得最好的 Heptabase 承诺的自动化最少**。

> **两个独立失败模式，通常被混为一谈：用户不会形式化，而且识别器也不够可靠到能代劳。**

## 3. 统一的理念

它们不是要被混合的两个选项：

> **对话是输入面。执行是结构的来源。仓库是结构的裁判。**
> **用户永远不画图；图从"实际发生了什么"里长出来，不从"你说了什么"里猜出来。**

分界线是可验证性：

| 来源 | 可验证性 | 实测 |
| --- | --- | --- |
| 从**散文**推断结构（对话文本、意图） | 不可验证 | 规格挖掘 **90–99% 误报率**；调平衡时 63% 精度；**无一交付给开发者** |
| 从**执行**推导结构（工具调用、文件、测试、提交） | 可重放验证 | Photoshop 动作存活、Selenium 录制崩溃：**"轨迹建立在稳定符号 API 上就能泛化，建立在渲染界面上就不能"** |

**工具调用就是稳定的符号 API。** 而 Coze/Dify 必须问用户要结构，**因为它们没有地面真相**——它们编排 API 调用，无人知道实际发生了什么。

> **仓库是一个它们没有的结构裁判（structure oracle）。这是本产品在交互层唯一的不公平优势。**

## 4. 三个成本模型（为什么这样是对的）

**① Grounding 成本（Clark & Brennan）** —— "最小协作努力"最小化的是**总**努力。十一项随媒介变化的成本中，两项决定成败：**formulation（组织表达）** 与 **fault/repair（出错与修复）**。对话在两项上都接近零；DAG 在两项上都是灾难（执行前必须完全指定；改一个节点要动图）。
→ **硬约束：任何加进来的结构都不得抬高 formulation 成本。**

**② Berrypicking（Bates 1989）** —— 信息需求**在过程中演化**，终点在起点时并不存在。要求用户开始前选工作流 = 要求他指定一个此刻不存在的东西。
→ **"随口的"和"正经的"不是两类任务，是同一个任务的两个阶段，而第一句话时无法分辨。**

**③ 渐进承诺（progressive commitment）** —— 这个名字学术检索**零命中**，可以拿走。基底有二：Marr 1976 的**最小承诺原则**（"永远不要做以后可能得撤销的事；永远不要过早承诺于某一种可能性"），以及 Arrow & Fisher 1974 的**准期权价值**（推迟不可逆行动以保留根据未来信息行动的能力，本身有价值）。
→ 注意与**渐进披露**的区别：披露是纯信息性的（Nielsen），**完全不处理状态与不可逆性**。二者不是同一件事，配对使用时必须分清。

**统一表述**：把交互表示成**偏序**而非全序。对话是承诺最少的表示；结构不是用户画的图，而是**运行时逐步累积的约束集**——而这些约束 v5 的 runtime 已经在生产（读集/写集、合并顺序、Verifier 封印、saga pivot）。

## 5. 六条不可违反的约束（每条带证据）

**C1 · 线性对话是默认，且不动它。**
中位任务只有 2–4 轮：LMSYS-Chat-1M 平均 **2.0 轮**；WildChat **约 59% 单轮**；Anthropic Clio（40 万会话/23.5 万人）**典型 Claude Code 会话约 4 轮**，且"测试"+"编排"**合计仅 5%**。
→ **任何带每会话前置成本的结构，摊销分母≈0。**
佐证：**用户不会成长到高级用法**——微软《Adopt ≠ Adapt》（约 12,000 用户 / 6 个月纵向）"**基本否定**"个体会学成高级用户，"用户习惯被证明是压倒性地黏着的"。**永久面向随手一问的用户设计。**

**C2 · 晋升必须是加法式的，绝不破坏性。**
三项对照研究一致：**破坏性自适应（重排菜单）输给静态**（Findlater & McGrenere n=27，三种顺序 p=.002/<.001/<.001），且**被 15/27 评为最令人沮丧**（对照"可自定义"仅 1/27）——约 8% 的速度损失换来 **15:1 的沮丧比**。**纯加法式自适应在 79% 准确率时快于静态，50% 时也不显著变慢**（n=48）。
→ **准确率是错的轴，破坏性才是。** 被提议的"任务"必须是**盖在现有对话之上的一层**：同一段滚动历史、同一个位置、**什么都不移动、什么都不改名**。

**C3 · 绝不让用户选，也绝不把选择权拿走。**
GPT-5 用自动路由取代模型选择器：推理模型使用率 **7% → 24%**（Plus）、**<1% → 7%**（免费）——**3 倍差距纯由"要求选一次"造成**。LMArena 整个产品就是并排对比，**只有约 12% 的人投票**。
但反向也成立：**系统主动的自适应同样输给用户可控的"可适配"菜单**。
→ **系统提议、一次点击接受、随时可退出。**（勿引用"果酱实验"——Scheibehenne 等 2010 年对约 50 个实验的元分析发现选择过载效应≈0。）

**C4 · 隐式层容忍噪声，显式层不容忍。**
Mylyn 是本领域**唯一带 p 值的生产率胜利**（编辑比，配对 t 检验 **p=0.003**，16 人中 13 人改善，最高 +172%；且**84.17% 的选择落在模型已标为正 DOI 的元素上**）。而它捕获的上下文**含约 28% 的假编辑事件**。
> **一个 28% 错误的产物带来了可测量的生产率提升，因为没有任何东西依赖它正确，也没有人需要批准它。**
→ **隐式层：永远采集、永不呈现为"待批准的产物"、容忍约 30% 噪声、只用于加权重与排序。**

**C5 · 显式衍生产物必须能被"执行"验证，否则不做。**
规格挖掘 **90–99% 误报**；LLM 解冲突与开发者本人一致率 **55–59%**；ALLOY（UIST'25，n=12）中**推导出的结构在正确性上输给手写**（9/12 vs 10/12），只赢认知负荷。而 METR 的 RCT：开发者慢了 **19% 却以为快了 20%**——**验证成本对付钱的人不可见**。
理论形式更糟：**一条轨迹是一个点，一个衍生出的过程/规格/计划是一个函数**；验证它要推理轨迹里不存在的输入，**严格地比手写更难**。
→ **杀死判据：若一个衍生产物无法通过执行检查、且输出空间开放（一个计划、一份规格、一篇设计文档）——不要建它。**

**C6 · 廉价的发散，只在回退可信时才廉价。**
每一个上线的显式分叉入口都失败于**可发现性 + 怕丢东西**：**ChatGPT 在 2026-02 的网页更新里直接删掉了版本箭头**（235 条回复投诉，到 2026-08 仍未修）；Cursor 的文档自相矛盾，用户原话"其中一个会丢数据"。
→ **"恢复对话 / 恢复代码 / 两者都恢复"必须是三个有明确标签的不同动作。**

## 6. 交互架构：四层

```
L3  显式衍生产物   极窄 · N=2 才提议 · 重放验证 · 可逐字面量拒绝
L2  晋升与提议     加法式一层 · 轮次边界 · 阈值由 C/B 推导
L1  隐式上下文     Mylyn DOI · 永不请求批准 · 容忍 30% 噪声
L0  线性对话       不动它
```

### L0 · 线性对话（不动）

零改动。所有结构都发生在它**之上**或**之下**，从不发生在**它里面**。

### L1 · 隐式上下文（可靠价值的全部所在）

**数据模型（抄 Mylyn，这是唯一带 p 值的）**：

- **交互事件 = 6 字段**：`time, kind, origin, contentType, handle, delta`
- **上下文** = 该任务激活期间的事件子序列 + 结构关系 + 每元素权重。**没有别的。**
- **随交互增长，不随代码库规模增长**（约 1 MB/月/人）

**DOI 公式（含关键的重置技巧）**：

```
interest = 0; decayStart = firstEventFor(e)
for event in eventsFor(e):
    interest += SCALING(event.kind)
    if interest < DECAY(decayStart, event): decayStart = event   # ← 重置
DOI = interest − DECAY(decayStart, lastEvent)
DECAY(a,b) = |eventsBetween(a,b)| × SCALING(KIND_DECAY)
```

**重置是关键**：衰减到负的元素，**一碰就立刻变正**，不必从 −N 爬回。
两个阈值：**DOI>0 = 可见**，**DOI>10 = 地标**（且作为自动检索的种子），**<0 = 完全过滤**。兴趣度向父级（文件→模块→项目）指数衰减传播。

**必须修 Mylyn 没修的那个洞**：它只有一套全局常数，数据显示**同时在两个方向失败**（2.06% 的选择落在已衰减出视野的元素上；两位被试点了 225 和 210 次"降低兴趣"）。作者明确指出模型**"对任务的生命周期是盲的"**。
→ **常数必须按上下文生命周期变：年轻的上下文慢衰减、宽搜索；成熟的快衰减、窄搜索。**

**同时不要重蹈它的另一个覆辙**：Mylyn 里"聪明的那一半"（预测式检索 Active Search）**只有五个用户重复使用过**，活下来的是无聊的那一半：**捕获、过滤、恢复**。

### L2 · 晋升与提议

**决策规则**（Horvitz 期望效用几何的可实现形式）。令 `p` = 这段对话是正经任务的概率，`B` = 事后补结构的成本，`C` = 拆掉不想要的工作区的成本，`K` = 问一句的成本：

```
p <  K/B          → 沉默
K/B ≤ p ≤ 1−K/C   → 提议
p >  1−K/C        → 直接做
```

**建 UI 之前先算这个**：当 `K(1/B + 1/C) > 1` 时**提议区间为空**——不存在任何 p 使询问最优，只能永远做或永远不做。**"要不要把它变成一个任务？"这类提示大多数都不通过此检验。**
→ **不通过就删掉提示，选一边站。**

**`C` 是唯一能靠设计控制的项**，也是全部证据所在（见 C2）。

**触发信号（绑定到已经会发生的事，不做仪式）**：同一条消息上出现**第二次分叉**、会话**跨过 N 轮**、**隔天以上的恢复**、**重复的测试失败**、一次**提交**。
（**不做每周摘要**——"人们很少回头"，而且仪式性复查是唯一零证据的机制。）

**时机**：**在完成的轮次边界发出，绝不在生成过程中。** 随机时刻打断 vs 任务边界打断的代价：**恢复时间长最多 30%、错误最多 2 倍、负面情绪最多 2 倍**。

**模式必须可见且对称**。"随手聊天 vs 被跟踪的任务"是一个模式问题，而实测显示：**用户自己保持的模式状态防止模式错误的效果比最显著的视觉反馈还好约 3 倍**（ω² 15.6% vs 4.8%），**而系统保持的"锁定式"模式在统计上与完全没有指示器无法区分**（p<.33）。
→ **自动晋升是实测中最糟的那一档。** 缓解只有：常驻、不可错过、**且退出与进入代价对称**（相称努力原则）。

**一条反直觉的补充**：人**偏好可逆的决定（66.3%）但对其结果满意度更低**（Gilbert & Ebert, p=.03）。
→ **让"提议"极易撤销，但让"工作区一旦进入就感觉是定下来的"。**

### L3 · 显式衍生产物（极窄）

只有满足全部四条才做：

1. **N=2 才推导，绝不 N=1。** 从单条轨迹泛化是那个无解的部分；**两条相似轨迹之间的差就是泛化本身**——变了的是偶然的，没变的是本质的。**这把推断问题变成集合运算。**
2. **用重放验证，不用阅读验证。** 交付时附"拿它对着来源轨迹跑一遍"并 diff。**把验证成本从 O(所有未来输入) 压到 O(1)。**（ALLOY 最重要的功能是执行按钮，不是那张图。）
3. **泛化逐字面量可见、可拒绝。** 内联渲染 `{{feature_branch}}` 而非 `feat/auth-x`——**每个占位符都是一次推断，逐个标注**，让用户拒绝一个占位符而不是审计整个产物。
4. **保留轨迹；产物只是指向它的有损索引。** 每个产物链接到证成它的那段轨迹，原始轨迹保持可查。**产物错了就回退到证据，而不是去调试一份摘要。**（Letta 的纯文件系统 74.0% 打败 Mem0 的结构化抽取 68.5%——**抽取销毁了信息**。）

**在知识峰值时刻推导**：成功后立刻提议，验证成本随延迟快速上升。

## 7. 可建的机制清单（全部带证据）

| 机制 | 证据 |
| --- | --- |
| **追溯式分叉，零仪式**：每条消息都是隐式分叉点；分叉是一个手势，结果**可见且非破坏性**（线程列表里的兄弟条目，不是隐藏箭头）；**明确声明继承了什么** | 失败模式一致是可发现性+怕丢，不是没需求；ChatGPT 两个 bug 都犯过（继承太少→太多） |
| **生成 N 个、展示 1 个、其余留在一个按键之外** | Dow 平行原型 n=33 真实点击率（44 vs 26）；而 GPT-5 路由与 LMArena 12% 说明**不能让人来选**——此机制同时满足两者 |
| **系统提议的下一步，每个一次点击** | CoNotate 的效果**完全来自点击建议而非手打**；ExploreLLM 中选项列表是最受欢迎的单一元素（5/8） |
| **安静的决策账本**，自动填充、**默认折叠**、仅在分歧时浮现 | Pail（CHI'25，11 位有经验程序员）确实带来并行探索，**但失败模式是"难以跟上 LLM 引发的变更与信息过载"——折叠是设计约束本身** |
| **切换时自动关闭，返回时带筛选还原** | TaskSnap（IEEE TSE 2026，55 位职业开发者对照）：编辑延迟 **4.81 vs 6.10 分钟**、两任务均完成 **88% vs 60%**、打开无关产物 **1.21 vs 20.28**。**清场是一半的效果** |
| **离开时生成"准备恢复"笔记**（agent 起草，用户确认） | Leroy & Glomb（Organization Science 2018）四项研究一致降低注意力残留且不损害打断源；**而让用户自己记笔记是弱条件**——给两种自动线索的开发者成功率是记笔记组的**两倍** |
| **"你不在时变了什么"渲染成有序叙事，不是 diff** | 开发者明确抱怨版本历史"无序、冗长、认知负担重"；**情节式排序优于罗列孤立细节** |
| **挂起的工作保持可见**（常驻"停放中"条带） | 可见度 <25% 的挂起窗口返回时间显著长于 >75%（t(20)=3.131, p<.005）——**仅仅看得见就是起作用的提醒** |
| **回退 + diff 作为主安全网**：每轮 checkpoint；三个动作分别标注 | InkSync：验证使被接受的错误编辑减少 **44%**，审计抓出多达 **73%**。**验证界面胜过探索界面——diff 和审计轨迹赢过地图** |
| **每一次撤销都记为带标签的负样本** | 撤销事件作为可用性问题指示器**误报率 0%**，暴露 **92% 的严重问题** |

## 8. 明确不做

| 不做 | 理由 |
| --- | --- |
| **画布 / 空间界面** | **零篇发表的留存率胜利。** Kosmik 做 8 年后 2026-05 关停；napkin.one 转回单列；Obsidian Augmented Canvas 累计 7,839 下载、两年未发版；tldraw "make real" 两周万星**从未成为产品**。唯一健康的 Heptabase 靠**手动**意义建构。**原因：空间布局是"现在付、以后收益"的成本，而多数任务在收益到来前就结束了。** 且没有识别器的画布是垃圾累积器，而**识别器正是没人做出来过的那一半** |
| **结构识别器（从散文/布局推断意图）** | Ink & Switch 三次尝试后原话："**我们总体上怀疑这件事能否做到可靠**"；Tinderbox 主动移除；空间解析自己的结论是"**歧义是用户的意图，不是解析器的缺陷**" |
| **让用户命名 / 分类分叉** | Aquanet：人靠**位置和复制**表达关系，**从不**靠有类型的链接。任何"这是什么类型的分支？"对话框**都重新引入了用户拒绝的那个形式主义**。Giornata：标签平均 1.8 词、创建后基本不改（**全部被试整个研究期间仅改过 12 次**），**14.8% 永久无标签**——把这 14.8% 变成默认形态 |
| **每周/定期回顾式摘要** | "人们很少回头"；**GTD 每周回顾零实证支持**；且它是一个复核队列，必然被忽略（Copilot 评论被忽略问题） |
| **自动任务边界检测** | Bardram 试过（RFID）："太粗、太不精确……**很难判断什么行为该触发一次活动切换**"，最后退回人工信号。**自动推断"相关性"，让"边界"保持廉价、延后、由人来划** |
| **要求用户先声明任务才能开始** | 见 C1/C3。**每段对话从第 0 个事件起就是一个上下文，无名、无标题** |
| **让用户来编排结构（DAG 编辑器）** | PromptChainer 退化到 4 个案例用户——**人来编排时结构成本只是被推走了，没有消失** |
| **生成式 UI（模型现场产出界面）** | 76 用户 380 查询：**50.8% 胜 / 8.2% 平 / 41.1% 负**——掷硬币，且胜出主要在审美 |

## 9. 与 v5 的接合

v6 的 L1 与 v5 的读集足迹**是同一份数据的两个用途**：

| 数据 | v5 用途（协调） | v6 用途（交互） |
| --- | --- | --- |
| `used:[{path,hash}]` | 失效检测的读集（基率放大器） | DOI 的 selection 事件 |
| `generated:[{path,hash}]` | 写集、冲突预测 | DOI 的 edit 事件（权重更高） |
| 工具调用序列 | saga 逆操作登记 | 交互事件流 |
| Verifier 结果 | 封印（ADR-0007） | 晋升触发信号 |
| 事件 `seq` | 因果顺序 | 衰减计数的时钟 |

**一次采集，两处使用。** 这也意味着 v5 §11.3 的 **R1′（写者成为黑板公民 + stream-json 足迹采集）同时是 v6 的前置条件**——不需要为交互层新增采集管线。

而 v5 §10.1 那条"产品必须可证明地不是编排器"在 v6 里的对应表述是：**用户永远不画图。**

## 10. 证据分级（诚实标注）

**测量过的**：Mylyn 编辑比 p=0.003（n=16，4 个月现场）；破坏性 vs 加法式自适应差距（n=27 / n=48）；打断时机 30%/2×/2×；模式反馈 3 倍效应（ω² 15.6% vs 4.8%）；TaskSnap 4.81 vs 6.10 分钟（n=55）；可见度 t(20)=3.131；Copilot 接受率 27–36% 对 51.5% 会话时间；DirectGPT 50%/50%/72%/25%（n=12，**限于"具体且局部的任务"**）；InkSync 44%/73%；Dow 平行原型 n=33（**同团队后续为零结果**）；GPT-5 路由 7%→24%；LMArena 12%；Adopt≠Adapt n≈12,000；书签 16%/4%（n=50）；规格挖掘 90–99% 误报；ALLOY 9/12 vs 10/12（n=12）；METR −19%。

**框架，未测量**：Horvitz 十二原则与 `p*` 推导（**LookOut 本身没有任何对照的准确率/收益评估，不能引为"混合主动有效"的证据**）；"廉价撤销许可激进行为"（方向被陈述过，**系数从未被测量——HCI 没有，AI 安全也没有**）；Shipman & McCall CHI'94 的渐进形式化成功主张（**三个研究部署的案例支持，无对照，无数字**）；Clark & Brennan 到 LLM 对话的迁移（**被论证，从未被测量**）；"Gulf of Envisioning"（**纯理论，零被试**）。

**明确超前于证据的部分**：**从对话追溯出结构，几乎没有实证文献。** Graphologue、Sensecape 都是小样本实验室原型，无纵向数据、无信任度数据。
→ **若要建 L3，你是走在证据前面，不是落在后面。这是本文档中风险最高的一层，也是最该最后建、最容易砍掉的一层。**

## 11. 验收与证伪

**L1 验收**：*一段会话结束后，系统能列出该会话的地标集合（DOI>10），且其中 ≥80% 是你会同意"这就是这次干的活的核心"的东西。* （对照 Mylyn 的 84.17%。）**不要求用户批准任何东西。**

**L2 验收**：*先实测 `B`（事后补结构的中位耗时）与 `C`（拆掉不想要的工作区的中位耗时），算出 `p*` 与提议区间。若区间为空，不建提议 UI。*

**L3 验收**：*任一衍生产物都能一键"对着来源轨迹重放并 diff"；且用户拒绝一个占位符不需要审计整个产物。*

**整体证伪**：给三个月内的日常工作记账——**你有多少次真的想从一段对话里岔出去但因为成本放弃了？** 若每周 <1 次，L2/L3 都不该建，只建 L1（它单独就有 p 值背书）。

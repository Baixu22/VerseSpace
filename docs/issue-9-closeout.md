## 唯一的代码改动，以及它为什么必须做

`DELETE /api/chat/threads/:id` 是全部端点里**唯一不可撤销**的一个：`packages/workbench/src/chat/threads.ts:732-743` 是 `rm(threadDir, { recursive: true, force: true })`，转录、恢复笔记、派生关系一并删除，事件日志里只留下「删除了」这一条观测。

准入前它的实际状态是判据 ③ 不满足：前端 `thread-list.tsx:126-137` 的 `Trash2` 按钮，经 `adapter.ts:103` 接到 `store.ts:859` 的 `deleteThread`，**中间没有任何确认**。其余所有 GUI 写操作都是追加式、幂等或可撤销的，只有这一个不是。

**为什么用原生 `confirm` 而不是软删除**：软删除会把「删了」变成「可能还没删」，与 `source=threads` 会话事件的追加式语义冲突——恢复卡会以为线程还在。一次确认比一个隐藏的墓地区诚实。换成内联对话框是纯 UI 美化，不改变这条判据。

**现行定位：Helmor = 写者中立的前提账本。** agent 走 R2 + stdin 通知，人走 R2′ + 恢复卡，都答不了的走裁决队列。下文 socket / saga 等候选机制保留作调研记录，不再是实施要求；不对沉默作安全保证。实际价值仍由 TF-0141 起算的真实使用窗口检验。

## 0. 一句话

**我们不做编排器。我们记录每个写者读到了什么，在它的前提被推翻时告诉它——而更好的做法是，把操作改造成不会推翻别人前提的形状。**

## 1. 主旋律：三层阶梯

```
能免协调的，免掉        ← CALM 定理：把操作改造成单调的
免不掉的，通知          ← MTPO：runtime 通知，agent 修补
通知不了的，才裁决      ← ISA-18.2：一条高门槛告警，很少响
```

这个顺序是硬的。**每往上一层，成本涨一个数量级；所以每一层的设计目标都是「把工作推给下一层之前，先尽量在本层消化掉」。** 绝大多数现有工具直接从第三层开始（把冲突丢给人），少数从第二层开始（消息/锁），**没有人从第一层开始。**

## 2. 剃刀（不变，且是唯一的功能取舍标准）

```
FO = (NT + IT) / IT        NT = 可忽略时间，IT = 单次服务时间
```

只有两个杠杆：**抬高 NT，压低 IT**。MIT（Cummings/Nehme）证明算入等待时间后容量预测**下调最多 67%——实测打三折**。代入真实值（IT≈10 分钟，NT≈15 分钟）：朴素 FO=2.5 → **实际≈1.7**。

而 IT 不是常数：合并冲突面按 N(N−1)/2 增长，**所以 FO 曲线会翻头**——这就是所有实践者都落在 2–4 的原因（七位以做 agent 为业的 Kilo 工程师、Willison、Anthropic 官方 3–5 后递减）。

> **不服务于「抬高 NT」「压低 IT」「压平 N(N−1)/2 项」的功能，一律不做。**

## 3. 第一性修正：两个写者，不是两个 agent

v4 把全部价值押在"多 agent 并发"上。**那是稀有场景，且天花板是 2–4。** 正确的重构：

> **一个 agent 会话从第一天起就已经在和别人并发**——和你的编辑器、和 `git pull`/rebase、和依赖安装、和 CI 产生的提交、**和它自己之前的会话**。
>
> **N=1 个 agent，N≥2 个写者。**

架构上免费：把文件系统、git、和**人**注册成"写者"即可，同一个引擎、同一个读集、同一个失效谓词。

**两次独立验证：**

1. **AgenticFlict**（14.3 万个 agent PR / 5.9 万仓库）总体冲突率 **27.67%**（Claude Code 25.93%），而它模拟的是**每个 PR 对它自己的 base**——即**分支 vs 主干漂移**，不是 agent vs agent。**即使 agent 之间完美去冲突，仍有约 28% 会和移动的主干冲突。**
2. claude-code#71879（"把待应用的 agent 编辑 rebase 到外部文件改动上"）**被以重复关闭**——说明不止一个人提过。Claude Code 只覆盖最窄的情况：编辑一个自读取后被修改过的文件 → 硬报错让你重读。**它检测不到"从文件 A 得出的结论现在为假"。**

**时间上的并发是普适的，空间上的并发是稀有的。** 主要对手是时间，不是另一个 agent。

## 4. 差异化的量化内核：读集是基率放大器

这是整份文档最重要的一条，它把"记录读集"从一个治理动作变成一个**数学上的必要条件**。

`PPV = pH / (pH + (1−p)F)`。在基率 p=2%、召回 H=90%、误报率 F=10% 时：**84.5% 的告警是假的**（每 1000 次写 → 116 条告警，仅 18 条为真）。要把 PPV 拉到 0.70，需要 **F ≤ 0.79%（d′≈3.7）**——近乎完美的检测器。

> **可行的动作不是造更好的分类器，而是提高 p：只考虑"与已记录的同一符号读取相重叠"的写。**
> 这把有效基率抬进 **10–30%** 区间，同一个检测器就给出 **PPV 0.5–0.8**。

**这才是记录读集的真正理由。** 不是审计，不是治理——是让告警在数学上可能成立。

配套的经验上限：**Bliss et al. 1995** 证明操作者**概率匹配**——响应率跟踪告警系统的可靠性，**没有悬崖，是一条线性斜坡，每损失一点精度就一比一地换来被忽略的告警**。**Wickens & Dixon 2007 荟萃分析：可靠性 0.70 是"不如没有自动化"的临界点。** Layman & Roden 2023（IDS 分析员对照实验）：86% 误报组比 50% 组**精度低 47%、耗时长 40%**。

## 5. 第一层：免协调设计（CALM）

**定理**：程序存在一致的、无协调的分布式实现，**当且仅当它是单调的**（"一致"指**汇流性**——结果在任意顺序/批次下确定，不是线性一致性）。

**一行判据：后到的事实会不会让这个结论变错？** EXISTS 类结论单调；NOT-EXISTS / COUNT / "值恰好是 V" / "我已看过全部" 不单调。

（正典对照：分布式**死锁检测**——环存在，新边只会增加环 → 单调 → 免协调；分布式**垃圾回收**——路径不存在，后到的一条边就推翻结论 → 必须"知道自己听全了" → 必须协调。同一个图可达性，**存在 vs 不存在就是全部差别**。）

### 5.1 agent 操作分类表

| 操作 | 支配的不变量 | 单调？ | 处置 |
|---|---|---|---|
| 追加文件 | 只增序列 | ✅ | 免协调 |
| 新增文件 / 模块 | — | ✅ | 免协调 |
| 加 import / 引用已存在的符号 | 外键 + Insert | ✅ | 免协调 |
| 在**新命名空间**建符号 | 唯一性，"选**某个**值" | ✅ | 免协调 |
| 在**指定名字**建符号 | 唯一性，"选**特定**值" | ❌ | 协调，或分割命名空间 |
| **删除符号** | 外键 + Delete | ❌ | 协调；或级联删除；或**墓碑 + 后台 GC** |
| **重命名** | = 删 ∘ 建 | ❌ | **加别名（单调）→ 迁移 → 事后移除** |
| **改签名** | "每个调用点都类型检查通过"（NOT-EXISTS） | ❌ | **加重载 → 迁移 → 事后移除** |
| **断言"测试通过"** | "不存在失败的测试" | ❌ 这是 GC 那一类 | 需要对被测区域**封印** |
| **标记任务完成 / "构建绿"** | 全局 NOT-EXISTS / COUNT | ❌ | 需要**封印** |
| 自增 id（迁移序号、端口） | AUTO_INCREMENT + Insert | ❌ | 协调，或托管一段区间 |
| **记录一次读（前提）** | — | ✅ | 免费——**这正是产生失效通知的东西** |
| 有下界的预算消耗 | `> Decrement` | ❌ | 托管 |
| 有上界的计数增加 | `> Increment` | ✅ | 免协调 |
| "符号 X 存在" / "文件含 S" | CONTAINS | ✅ | 免协调 |

### 5.2 三条逃生路（按优先级）

- **(a) 改造成单调** —— 墓碑、别名、先加后迁。**把协调移出关键路径。** 「重命名」→「加别名 → 迁移 → 移除」把一个必须协调的操作换成三个免协调的操作。**这比任何协调机制都便宜，是本项目最大的一笔杠杆。**
- **(b) 封印一个分段** —— 路径 glob / 模块 / 符号集上的租约。分段内免协调，只在跨段时协调（分段不变量汇流性；实测在跨段罕见时 **10–100×** 于线性一致复制，**跨段频繁时反而输**）。注意作者自陈：找到有效分段"可能是个繁重的过程"，**不可自动化**。
- **(c) 事后补偿** —— saga 逆操作。

**当前设计 = (c) 为主，(b) 可选，而 (a) 是我们尚未开采的富矿。**

### 5.3 一个必须记住的成本事实

Saito & Shapiro 的六轴分类里，我们选的是**多主、操作传输、语义调度、检测并由语义解决器（agent 本身）解决**——**每一轴上最贵的那个角**。Gray et al.（SIGMOD 1996）：朴素多主系统的并发更新率随主节点数 **O(M²)** 增长；**节点数与流量各增十倍，死锁/调和增加一千倍**。

该综述的处方恰好就是我们要做的：**快传播**（分歧窗口 ∝ 冲突率）、**切成小的独立对象**、**对象内优先使用单调结构**（只增日志、只并集合、单调递增计数器）。

## 6. 第二层：通知（MTPO / 建议式并发控制）

### 6.1 为什么必须是建议式

| 方案 | 实测（CoAgent，十个竞争负载） |
|---|---|
| 无协调并行 | 快，但**通过率仅 13%** |
| 2PL 悲观锁 | 每轮死锁 0.81 次，加速比 **1.04×** |
| OCC 乐观回滚 | 每轮回滚 0.95 次，**0.93×（比串行还慢）**，token 1.83× |
| **MTPO 建议式** | **1.4× 加速，正确性与串行差 ≤5%**，token 1.15× |

关键洞见：**"Partitioning constrains writes; the bug is in reads."** 写集完全不重叠仍会产生任何串行顺序都不产生的错状态。LLM 有经典事务没有的三种能力：判断冲突是否真推翻前提、只修补依赖失效值的那几步、为几乎每个写生成逆操作。**被通知的 agent 误判相关性的比例仅 5%。**

### 6.2 检测谓词：三层，按顺序建

**第 1 层 · 读集来源分级**（抄 Salsa 的 durability）。`node_modules/` `vendor/` `dist/` 生成物 = durable；`src/` = volatile。每 tier 一个计数器的版本向量。**每次写 O(1)、约 40 行、语言无关、零工具链、纯精度收益零召回损失。先做这个。**

**第 2 层 · 跨度限定的读**。记录字节/行区间而非文件；grep 记命中 hunk，读文件记真正进上下文的部分；有写入时按 diff hunk 重定位，**只在重叠时通知**。干掉最大噪声源（"读了 2000 行，改了第 3 行"）。

**第 3 层 · 导出面哈希（ABI 谓词）**，并把读拆成两种边：
- **依赖式读**（import / 调用）→ **只在导出面 hash 变化时通知**
- **主题式读**（正在改它 / 在推理它的算法）→ **方法体变化也通知**

实现：**tree-sitter `tags.scm`**，对每个 `@definition` 哈希 `definition_node.text` 减去 `body` 子节点。一个 parser 依赖覆盖所有主流语言。TS 可升级到 `tsc --declaration`（能抓 `string → string | null` 这类 tree-sitter 抓不到的类型变化）。

**永远抓不到**：只改方法体（改默认值、翻布尔、收紧校验、换异常类型）。**所有 ABI 式谓词按构造对此盲。当作已接受的、记录在案的空洞，不是待修 bug。**

### 6.3 三条硬性工程约束

- **不要建深依赖图。** rust-analyzer 迁到 Salsa 后内存 5–6 GB → **约 22 GB**。**我们的图只有两层：agent → {文件, 符号}**，需要的是反向索引 + 基于值的截断，**不是增量计算引擎**。这是最大的一笔架构节省。
- **不要拿结构化 diff 当谓词。** difftastic 在改动多的文件上扩展性差；**你需要的是投影上的相等判断，不是编辑脚本。**
- **红线案例**：TypeScript #63664——首次编辑拿新算的 `.d.ts` 哈希比存着的**文本**哈希（必然不等），再穿 `export *` barrel 走完传递闭包。**一次纯空白编辑重新产出 502/502 个文件**；真实 7800 文件工程每次首编辑失效约 1150 个、70–95 秒。**一个投影 bug = 约 1000× 过度通知 = 通道开局即死。** 主要工程成本不在图上，**在于把易变细节（位置、格式、顺序）挡在投影之外**。

### 6.4 两个阈值，不是一个

决策论切点 `θ* = C_FA / (C_FA + C_M)`：

- **面向 agent：θ ≈ 0.10，激进通知。** C_M 巨大（无协调通过率 13%），C_FA 只是一次额外推理且误判率 5%。**agent 是便宜且校准良好的第二级过滤器——这正是把 LLM 放在回路里的全部意义。**
- **面向人：θ ≥ 0.70**（Wickens & Dixon 临界点），**0.30 以下什么都不发**，且**聚合后再发，不要逐写发**。

### 6.5 二元 + 保守门槛，不要分级

**Zirk, Wiczorek & Manzey (2020)**：联合人机灵敏度平均秩 **保守二元 51.6 > 4级 31.6 > 3级 23 > 自由二元 13.7**；**漏报上保守二元显著优于其余全部**；**保守二元没有狼来了效应**。应用建议逐字：*"implementing conservative BASs in multi-task working environments."*

**Wickens & Colcombe (2007)** 摘要逐字：*"there was no benefit to a three-level system over a two-level system"*，且实测有代价（响应更慢、跟踪误差增大）。

**决定性的边界条件**：Wiczorek/Balaud/Manzey (2015) —— **当操作者能核验告警有效性时，LAS 优势消失**。**而你的场景永远能核验**（随时可以去看 diff）。

低于门槛的东西**不是第二个告警级别**，而是 agent/人在自然边界主动**拉取**的软摘要。**推送通道保持二元。**

### 6.6 投递时机

**在 agent 的下一个工具调用边界投递，绝不在推理中途。** 三条独立理由汇合：MTPO 的可串行化论证依赖**单向（低序→高序）**投递（双向会重新引入环）；Iqbal & Bailey 实测在断点处投递**降低挫败感 20%、反应时间 25%**；而 LLM agent 在工具结果边界的工作状态**已外化在上下文里，恢复延迟≈0**，与人不同。

**唯一例外：若 agent 的下一个调用正是写入失效区域，则同步阻塞该调用——那不是打断，那是封印点。**

机制：`CLAUDE_CODE_MESSAGING_SOCKET`（Unix socket / Windows 命名管道，首行 `{"type":"auth","token":...}`），**在活跃轮次的工具调用之间投递**。这落在 KV 缓存安全的一侧（**只追加**）。

**KV 缓存红线**（缓存是前缀匹配，任何位置改一字节则其后全废；渲染序 `tools → system → messages`）：
- 允许：只追加、写文件、加后缀、开子 agent、挂起让 TTL 过期（代价=一次前缀重写）
- **禁止**：编辑/删除任何中段消息、重排序、中途改系统提示、**中途增删工具**（工具排最前，直接作废 100%）
- **陷阱**："裁掉旧消息省 token"**反而更贵**。压缩按构造是全量缓存重置。
- 每车道能力门控用 **屏蔽 logits，不要移除工具**。

## 7. 第三层：裁决（ISA-18.2 纪律）

`notify_human` 已有 9 个发射点遍布三个状态机与 scheduler，把它从 printf 变成真队列：

- **合理化五准则**：异常 / 有后果 / **要求动作** / 相关 / 唯一。**没有既定动作的不是告警。** 工业实测砍掉 40–60% 事件。
- **优先级 = 后果严重度 × 响应时限**，绑 SLA（<5min / 5–30min / 30min–2h / 数小时）。合理化后目标分布 5%/15%/30%/50%；**>25% 为"严重"即分级失败**。
- **首因 + 因果抑制**：一个失效依赖打断 30 个会话 → **一条，挂 30 个**。
- **搁置必须自动到期**（5min–4h），搁置数本身是 KPI。
- **容量硬上限**：**~1 条/10 分钟可持续，~12 条/小时上限，10 分钟内 ≥10 条 = 洪泛**。
- **NEWS2 式单参数越级**：碰认证代码 / force-push / 检出密钥 → 单独升级。
- **卡片用 SBAR**（结尾是 Recommendation）：**打断人的东西必须带建议，不能带问题。**
- **挑战-应答**：agent 断言 "tests pass: 412/412"，人核对**产物**而非声明。合并闸门 ≤5 项、60–90 秒、只放"漏了就死"的项。

### 7.1 产品承诺的红线

Meyer 的依从/信赖区分 + Gérard & Manzey 基准（PPV .9→.7 依从掉约 25%；NPV .98→.93 信赖掉约 25%，**信赖脆弱得不成比例**）：

> **争取依从，不争取信赖。** 承诺是"**我说话的时候，你信我**"，**绝不是**"我没说话你就安全"。
> **永远不要把沉默包装成安全保证。**

这与"往精度错、接受漏报"自洽——因为漏报在这里是**自纠正的**（类型检查/测试/复核会在下游抓住），而误报**消耗最稀缺的资源（上下文）并教会人静音通道，一旦静音有效召回归零**。

## 8. 界面：显示争用面，不是显示 agent

### 8.1 顶层该是"抽象功能"层

| Rasmussen 层级 | 内容 | 现状 |
|---|---|---|
| 功能目的 | 每条流的**承诺** + 所有流落地后仍须满足的不变量 | **无** |
| **抽象功能** | **必须守恒的东西**：单一自洽构建、每个符号的**不重叠所有权**、唯一迁移顺序、测试全绿 | **无** |
| 泛化功能 | 维持守恒的过程：rebase/merge、复核、裁决、测试 | 部分 |
| 物理功能 | agent、分支、worktree、会话、预算 | 部分 |
| 物理形式 | 文件、diff、面板、日志 | **所有产品都堆在这里** |

**顶层最重要的对象是「守恒违约」：被一条以上的流认领的符号/文件/契约，及由此产生的合并顺序约束。这个东西今天在任何地方都没有表示，且无法通过读 N 份 diff 重建。**

形态：**不是"5 个 agent 面板"，而是一份显示仓库争用面的共享产物**——认领/所有权地图，每条流的承诺意图挂在上面。

### 8.2 五条设计规则

- **R1 · 感知优先于预测。** Jones & Endsley：**76.3% 的态势感知错误在 Level 1（感知）**，仅 3.4% 在 Level 3（预测），主因是"数据在屏幕上而操作员没看"。**预算花在"让关键那条被看见"。**
- **R2 · 显式画出手段-目的链接**（Ham & Yoon 2001 显著优于不画）。但收益**只在复杂条件下出现**。
- **R3 · 双向暴露隐藏依赖**（Green 的正典例子就是电子表格单元格——**你的情况完全同构**）。
- **R4 · 不要在残缺遥测上建抽象层显示。** Reising & Sanderson：仪表化只是"勉强够用"时，**EID 性能下降比传统显示更剧烈**。**一张由不完整状态喂养的抽象显示，比原始 diff 更糟，因为它看起来很权威。** → **足迹采集完整之前不发这张图**，且算不出某个守恒时必须**可见地降级**。
- **R5 · 监视与诊断是两张不同的显示。** Burns 2000：**低集成度 → 最快的故障检出；高集成度 → 最快最准的故障诊断。**
- **R7 · 提供专门的变化检测工具，绝不依赖人去注意。**（Durlach）**"你上次看过之后变了什么"是一等公民功能**——而它和"会话恢复安全"是同一个机制，一个给人一个给 agent。
- **R9 · 警告：让机器可读会增加"接管"而非"信任"。** Borst 2017：显式手段-目的链接使被试**倾向于从自动化手中接管控制，与是否真有故障无关**，而接受/拒绝次数无显著变化。**可读性和吞吐量在这里对立，不能都要满格。**

### 8.3 注意力预算（SEEV）

`注意力 ≈ sS − ef·EF + ex·EX + v·V`。按可控性排序：

- **努力 EF —— 最强负项，也是你真正拥有的。** 每个需要**切过去**的面板都是努力。**把所有裁决相关的东西并置在一个区域。**
- **期望 EX** —— **不停变化的面板会训练出对"有意义变化"的低期望。喋喋不休的 agent 日志会主动压制你注意到那唯一重要的事件。**
- **价值 V** —— 必须编码进显示，队列按价值排序。
- **显著性 S** —— 最便宜最弱；前注意特征**只在背景安静时**弹出。**显著性是稀缺预算。**

加上警觉性 20–30 分钟起衰减（30 分钟检出率降约 15%）：**被动监视不是一个设计选项。人的工作是一个队列，不是一块表盘。**

### 8.4 EID 的诚实边界

Bennett & Flach 三十年综述：EID"在约束是**法则驱动**的工作域里取得显著成功"（热力学、飞行动力学）；对**意图驱动**的域"需要完全不同的技术"，证据薄得多。**代码库是意图驱动的——方法可以借，效果量不能借。** 可用的一般化（Naikar）：**"在非常规或复杂任务上普遍优于既有界面，在常规或简单任务上无劣势。"**

### 8.5 Naur：只用可证伪的版本

Naur 的死亡条件（"程序的死亡发生在拥有其理论的团队解散之时"）**在这里按构造每天满足 N 次**——**agent 运行时本质上是一台理论销毁机**，人类团队十年的衰变在这里压缩成几周。

但"理论持久化"作为主张**不可证伪**；**"agent 没有第二次推导出同一个错误结论"可证伪**。

**裁决**：理论持久化不是协调的替代品，**它是协调显示所由以构成的材料**。抽象功能层与被持久化的理论**是同一个产物的两个视角**——显示是被外化的理论，人的裁决是保持它为真的批注（Mackay 的飞行进度条，对象换成仓库：**自由文本批注 + 用户控制的空间排序 + 跨会话持久**）。

要发的句子是"**这次运行留下一份持久的、可批注的模型，记录仓库的争用面以及每个决定为何如此**"，**不是**"理论持久化"。

## 9. 合并：杠杆在上游，不在算法

**可行性已实测**（helmor 本仓库，2053 文件，git 2.51，Windows）：`git merge-tree --write-tree --name-only` **热态 33 ms**。N=20 两两 190 次 ≈ 7.6 秒，滚动集成 20 次 ≈ 0.8 秒。**N² 项在任何笔记本能承载的 N 上都无关紧要。**

**但真正的成本在别处**：Crystal 研究发现**约 33% 的冲突是构建/测试失败，VCS 完全看不见**——抓它们要跑类型检查/测试，分钟级。

**规模曲线**（AgenticFlict）：**2 行 → 9.9%；25 行 → ~30%；46–185 行 → 32–33% 平台期。** 小改动帮助巨大，**但只在最底部，然后就平了**。

**唯一上线过的系统是靠更笨赢的**：微软 **ConE** 部署 234 仓库，**故意不做推测式合并**，只用便宜的文件重叠信号；**26,000 个 PR → 775 条通知（3%），70% 有用，>90% 受访者愿继续用**。明确拒绝 ML，理由逐字："精度太低，误报太多会让工具无人使用。" 而十五年的学术先例（Palantír / Crystal / Cassandra / WeCode / Syde）**商业采用为零**。

> **结论：合并层只投入"便宜的安全网"——ConE 式写集重叠账本 → 连续 `git merge-tree` → Zuul 式滚动集成分支。真正的力气花在上游把变更切小。**
>
> 反方论证（DORA 支持的是 <3 条活跃分支、生存期 <1 天）的正确反驳是：**主干开发假设的是"可以被要求每小时提交的人"；而 agent 可以被强制——任务分解是你控制的。** 2 行/9.9% 那个点，**只有在运行时规定变更粒度时才够得着。那是调度问题，不是合并问题。**

可选的高价值补充：**Uber BLRD 的经验交换律测试**——对 C₂ 的检查在 `H` 和 `H+C₁` 上各跑一次，结果相同则两者可交换、可任意顺序落地。**这是你能在 git 上真正算出来的补丁交换律**（Pijul 的理论正确但不可加装到 git 上），也是唯一能抓语义独立性的机制。

**硬规则：永远不要在 agent 运行期间自动更新它的 worktree**（ezyang 实践原话："I want to delay worktree updates until I am ready"）。`git-branchless` 被实测为"buggy, failed to reliably restack"，不要依赖。

## 10. 明确不做

| 砍掉 | 理由 |
|---|---|
| a2a / 互聊协议 | Google 数据：独立并行放大错误 **17.2×**，中心编排 4.4×；MAST：**32–37% 失败是智能体间失配**；且已被引擎商品化 |
| **四提供商里的三个 HTTP 纯文本路径** | 无工具调用 → **产不出读写集 → 无法参与协调**。留 claude CLI，之后加 codex CLI |
| **Verifier 加 LLM 裁判** | LLM-as-judge 在专业领域与专家一致率 **60–68%**，且裁判之间**错误相关**（投票收益远低于直觉）。"LLM-as-judge is not a verification layer. It is a second failure mode." 正确扩展方向是**蜕变测试**与变异测试 |
| **分级/似然告警** | 见 §6.5 |
| **CRDT（Automerge/Yjs）** | **买的是收敛不是正确性**；跨对象不变量证明上需要协调；文本 CRDT 会把两个 agent 的编辑收敛成语法正确但编译不过的代码。`events.jsonl` 已是唯一需要的 CRDT（G-Set） |
| **深依赖图 / 增量计算引擎** | 见 §6.3 |
| **Chandy-Lamport 全局快照** | 约束是 FIFO 通道；agent 一旦绕过中介（裸 shell、编辑器、子进程）就拿到不一致切分。**预分配序 + 每对象版本轨迹**已足够 |
| **跨车道上下文再平衡 / 中段裁剪 / 全局填充率水位线** | 没有共享池可平衡；中段裁剪省的不如赔的 |
| **Jujutsu（现在不做）** | `jj-lib` 无稳定 API；**op log 仓库全局而非按 workspace**（一个 workspace 的 undo 能撤另一个的操作）；冲突提交无法表示进 git（`.jjconflict-*` 目录会让 CI/PR 看到垃圾）；`working-copy.eol-conversion` **忽略 `.gitattributes`**——与已修的 CRLF 竞态直接冲突；**且它透明自动更新工作副本，违反 §9 硬规则** |
| **Plan 9 式 per-session 命名空间** | Windows ProjFS 无 Node/Bun 绑定、需管理员启用、旗舰消费者已被微软放弃。**worktree 就是命名空间**，显式化为 `view.yaml` 并在工具调用 broker 层校验 |
| **手动工作流 DAG / 取代对话的工作台 / 数据库依赖 / Agent SDK 内嵌** | v3 已排除，继续有效 |

### 10.1 一条硬性设计约束

市场对"编排层"这个品类已有判决：*"Simple systems look boring, but they win because they're testable, debuggable, and cost-controlled. **The agents never talk to each other.**"* / *"我们放弃了多 agent 编排框架。理论上很美，实践中只增加复杂度。"*

> **产品必须可证明地不是编排器。** 观测与通知，永不指挥。零配置、零 DSL、无"定义你的工作流"。**冲突不存在时它完全隐形。**
> **一旦它要求用户先声明工作流，它就变成了那个被抛弃的东西。**

这条与 CALM 一致：JIT 从不要求程序员声明假设，**假设是运行时观测出来的**。

## 11. 产品形态、命名与顺序

### 11.1 商业现实（必须正视）

- **叙事位被厂商占了。** Claude Code 文档逐字：*"When a change in one session breaks what another is building on, Claude can warn that session before you notice."* GA、默认开启（v2.1.224+ / 原生 Windows v2.1.234+）。
- **但机制没被占。** 它是 `ListAgents` + `SendMessage`，**模型自愿调用**——没有读集、没有检测、没有确定性。**"agent 根本没意识到该发"正是常见情况。**
- **隔壁品类死于收费不是死于分发。** Bloop 关停公告逐字：*"Thousands of software engineers use Vibe Kanban every day… but the vast majority are free users and we couldn't find a business model that we could get excited about."* Crystal→商业化 Nimbalyst；Conductor→云。**每个幸存者都离开了"本地优先的个人开发者"。**
- **推论**：无服务器/无数据库/本地优先这组工程约束，**正好是让收费不可能的那组约束**。

### 11.2 结论：改的是"卖什么"和"叫什么"，不是架构

**形态**：开源 hook / 库，一条命令安装。**多会话协调留在代码库里、不做宣传**，等用户开出第二个写者时它已经在工作。

**命名**：不认领品类。旗号用 **context rot**（有 arXiv 论文为此场景做形式定义 + Salesforce/Harness/LogRocket/MindStudio 术语页）；**机制独占一个窄术语：`stale premise` / 前提失效**（无人占用）。产品名词保持谦卑：**hook / linter / daemon，不要 orchestrator**。（**避开 "agent sprawl"**——已被企业身份治理彻底殖民。）

**分发楔子**：**hooks，不是 MCP 注册表**（约 9,652 个 server，发现性已死）。`PreToolUse`/`PostToolUse` 给确定性读写观测，而 **Cursor 支持加载 Claude Code 的 hook 配置——一次集成，多家厂商**。这让你站在厂商层**之下**而非**旁边**，是唯一能在被吸收时活下来的位置。

**四个单人模式钩子**（发 3 号被安装，1 号交付第一天价值，2 号留住人）：

1. **对人与 git 的陈旧前提检测**（最可信）
2. **会话恢复安全**——恢复时 diff 仓库与存下的读集，注入"你的 37 个前提里有 4 个现在为假"（**产品价值最高，最强留存**）
3. **context-rot 体检** `npx <tool> doctor`（最好的获客、最弱的护城河；学术数字：**356 个代表性仓库中 23.0% 存在陈旧代码元素引用**）
4. 返工计量

### 11.3 顺序

**Sprint 0 · 前置（不加功能）**

1. **修 CORS/鉴权**：`ui/server.ts:238` 每个响应带 `access-control-allow-origin: *`；`POST /api/agent/run` 是任意 agent 执行、`PATCH /api/config/chat` 写 API key。**这是漏洞不是待办。**
2. **抽 L0 进程 supervisor**：三处 spawn 三套纪律，只有 `verifier/index.ts:34` 是对的（`taskkill /T /F`）；`chat/threads.ts:165` 裸 `kill()` 在 Windows 上杀 cmd.exe shim 而孤儿化 claude；**`agents/runner.ts:107` 无 kill、无超时、pid 不落盘、输出无界累积在内存**。结构化并发（scope 拥有进程组）+ OTP 升级放弃（60 秒内崩 3 次 → failed → 上抛 goal → 停派发）。**行业公开记录的第三大杀手就是并行 agent 下的孤儿进程与内存耗尽，而按车道计量进程/内存是竞品全员空白。**
3. **blackboard 真写前置条件**（CAS on version+hash）；`queue.yaml`/`registry.yaml` 从"单文件装数组"改"一条一文件"；**改掉 `fault-tolerance.test.ts:96` 那条把丢更新断言成正确的测试**。
4. **`runOnce` 单写者**：锁覆盖 `sync`/`dispatch`/API 全路径，用 `O_EXCL` 而非 check-then-write（`watcher/lock.ts:31`）。
5. **升 claude CLI 至 2.1.234+**，并决定 runtime 与 agent 是否同处原生 Windows 一侧（**WSL2 ↔ 原生 Windows、宿主 ↔ 容器互相到不了**）。做最小连通性验证：起一个 `-p` 会话、从外部往其 socket 投一条、确认在工具调用之间收到。**这是整套架构唯一的二元风险，值得在写任何功能代码前用半天打掉。**
6. **在本仓库 `workbench init`，用它推进下一个里程碑。**

**R1′ · 写者成为黑板公民** —— 会话/编辑器/git 统一注册为写者 + stream-json 足迹采集（`chat/threads.ts:338-343` 与 `:355-363` **已在解析 `tool_use`/`tool_result`**，现在渲染完就丢；采集是既有解析点加几行落盘）。事件 schema 借 W3C PROV 词汇：`{seq, ts, activity, agent, used:[{path,hash}], generated:[{path,hash}], facets}`。用 `--session-id <uuid>` 由 runtime 铸币。
**验收**：*一段会话结束后，runtime 能回答"这个写者读了哪些文件的哪个版本、写了哪些"。*

**R2′ · 陈旧前提检测（单写者版）** —— 对人的编辑与 git 变动做检测，恢复会话时注入失效前提清单。
**验收**：*你在 IDE 里改了 agent 第 4 轮读过的文件；在它下一个工具调用边界，它收到带 diff 的通知并作出回应，全程记录在案。*

**R3′ · 多写者 + 裁决队列** —— 二元保守门槛、ISA-18.2 纪律、WIP 由小定律推导。
**验收**：*队列 24 小时内速率 ≤6/小时、无洪泛、严重项占比 ≤25%、每条都带既定动作。*

**R4 · 发行** —— 先修 `ci.yml` 的 15 处 tab。

### 11.4 每车道计量（竞品全员空白）

从 `usage` 对象取：**绝对输入 token**（**不是填充百分比**——"60% 开始退化"是民间传说；一手文献测绝对长度，NoLiMa 在 **32K** 处 12 个模型里 10 个跌破短文本基线的 50%）· `cache_read`/`cache_creation`/`input_tokens` 三分 · **每轮缓存命中率**（掉到零 = **有人改了前缀，那是 bug**）· 压缩次数 · 工具结果占比 · 连续失败编辑数 · **全局：未复核 diff 积压**。

阈值：工具结果 >40% → **只做可恢复的工具结果驱逐**（丢内容留路径）；缓存命中率下降 → **不要压缩，查前缀**；压缩 ≥2 或连续失败 ≥2 → **挂起车道，从文件系统笔记 + git diff 重播种，绝不从摘要的摘要**（Laban：**迷失后不会自行恢复**）；未复核积压超容量 → **准入控制，拒绝开新车道**。

> **注意**："N 个并发 agent = 抖动系统"这个类比**是错的**（车道不共享上下文窗口，没有故障信号，没有局部性）。**但它精确地搬家到"人的复核带宽"上**——那里有真实的共享资源和真实的故障信号（积压量），Denning 的负载控制在那里成立。

## 12. 证伪实验（写代码之前，一周）

给日常工作装记账本，出现下列任一情况记一行：(a) 某写者基于已过时信息干了活；(b) 两个并行产出**语义**打架（非文本冲突）；(c) 因记不清哪个会话在干什么而重复劳动或做错决定；(d) 想问"这个会话到底动过什么"但答不上来。

| 频次 | 裁定 |
|---|---|
| **每周 ≥3 次** | 命题成立，按本文执行 |
| **每周 <1 次** | 在为尚不存在的问题造工具。**但注意：按 §3 的重构，"写者"包含你自己和 git——先按新定义重数一遍再下结论。** |
| **痛点全在 (c)/(d)** | 产品是**外化记忆**（§8.5），不是并发控制 |

## 构建与后台验证

补充 `workbench ui --no-open`，E2E 启动服务时使用它。打包检查在独立工作区执行，避免依赖仓库 cwd。实际检查发现 JS 包按运行目录寻找相对资源会失败，同时发布清单漏掉了资源；现已相对 bundle 目录解析，并将 JS 包的资源输出到 `dist/ui` 后一同打包。

Windows 原生包与 JS 包均通过初始化、当前统计字段和内嵌新界面的检查；`npm pack --dry-run --ignore-scripts` 确认包含 14 个 UI 资源。仓库已有的跨平台二进制未被清理或覆盖，本轮构建检查使用独立临时目录。

持续检查入口：`bun run test:build`，也可用 `--native <路径> --js <路径>` 指定产物。打包与接口相关 21 项回归通过，类型检查通过。未发布到 npm 或远端。

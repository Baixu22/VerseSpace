## D5 · Q3 把 R2 从"写者间"扩展到"分支间"

### 机制草图(数据流级,全部复用现有部件)

```
fork POST
  ├─ thread.forked{child, parent, at_message}            (会话事件)
  └─ footprint.inherited{actor: child, refs: [父 footprint seq ≤ at_message]}   (世界事件;不复制内容)
                    │
                    ▼
premises.ts 投影:child 的读集 = 自身 footprint ∪ expand(refs)
                    │
watcher 每轮 reconcile:兄弟/人/外部 commit 写盘 → 读集比对 → premise_stale{actor: 写者, target: child}
                    │
delivery.ts → notifySession(child)  轮间注入(现有) / 排队下轮前(现有)
                    │
seal.ts PreToolUse:child 写入已知漂移区域 → exit 2(现有;新增 seal.decided 记录)
```

新增代码量:fork 处理器两行追加 + premises.ts 一个 `refs` 展开。其余零改动。

### (a) H1 的正确性边界

**该进读集的**:
- `used`(路径 + 调用时哈希 + 行级 span):是——三层判定(耐久分层 → span 重定位 → 导出面哈希)全靠它。
- `generated`(路径 + 结果哈希):**是,作为前提**。"我写了 X(hash h)"是 agent 的信念;兄弟覆盖 X 后这个信念为假。现状 R2 是否把 `generated` 当前提——需要补充;若否,父线程自己也漏这一类。
- span:是(重定位层需要)。
- 64KB 内容暂存:**否**。子线程通过 `refs` 引用父线程的暂存(diff 渲染时解引用),不复制——磁盘与 Windows FS 都禁得起这个省略。

**漏报(该报没报)**:
1. 父 agent 上下文里有、但不是 tool-call 得来的知识:用户粘贴的代码、用户口述的约束——足迹里没有,R1 也不允许从文本补。**接受**:下游自纠(agent 一读文件就发现)。
2. 父线程在分叉点**之后**的读——正确排除(子上下文止于 #k)。
3. `about_ts` 回填的旧分叉:回填 `thread.forked` 可以,回填 `footprint.inherited` **不可以**(无法知道当时的读集是否仍在 agent 上下文里)——旧分支读集从空开始。

**误报(报了不该报)**:
1. **模型上下文未继承**(D0 盲区):全部继承前提都是误报。前置检验,不可跳过。
2. **父线程曾压缩上下文**:CLI 压缩后 agent 可能已"忘记"早期读,足迹却记得 ⇒ 继承了 agent 不再持有的前提。缓解:耐久分层已按"耐久"降权旧读——需要补充其常数;建议 `footprint.inherited` 只引用分叉点前 N 轮/最近 M 条,常数取自现有耐久分层,不新造。
3. **grep/glob 洪泛**:一次 grep 命中 200 文件 ⇒ 200 条低耐久前提 ⇒ 兄弟随便写一处都触发。父线程今天已有此问题,H1 只是乘以分支数。需要补充:耐久分层如何对待 grep 产生的 `used`;若无区分,这是 H1 前必须先修的一处(D4 失败 3 的熔断在此)。
4. **分叉点前 agent 已被告知失效的前提**:父线程在 #k 前收到过 premise_stale 并已重读(新哈希),足迹里有旧读与新读两条——`refs` 展开须取**每路径最后一次**观测,否则子线程一出生就收到"已解决"的失效通知。一行代码,但必须写。

### (b) H4 touch-scope 与 C1 的摊销算术

C1(R6)的算术:每会话前置成本 T_s,会话中位 3 轮,收益只在"有另一个写者重叠"时兑现(概率 p_o,单次收益 V):

$$\text{每会话净值} = p_o V - T_s,\quad \text{用户不会成长} \Rightarrow T_s \text{ 不会随时间摊薄}$$

p_o 小、T_s 为正 ⇒ 净值为负 ⇒ C1 禁止任何 T_s>0 的每会话仪式。**这与频率无关**:换成每分叉事件,公式一样,只是次数变少——次数少不会让负值变正。所以 H4 成立的**唯一**条件是 T_s = 0(用户零输入,机器推导)。H4 的表述"分叉时刻是唯一零成本结构化时刻"是对的,但原因不是"低频可摊",而是"用户什么都没做"——一旦变成表单,C1 立刻回来,和低频无关(Adopt≠Adapt)。

touch-scope 的机器成本:从继承前缀的 `generated` ∪ 父线程 blackboardEffects 推导,毫秒级。所以成本侧没有问题。

**问题在收益侧**:touch-scope 是**预测**("这分支大概会写这些"),消费者是 merge-guard 的重叠账本——把预测重叠当信号发出,精度必然低于观测重叠。ConE 恰恰是靠"只发已发生的文件重叠、不做推测"拿到 3%/70% 的【文献引用】。R9 说往精度错。**结论:H4 的推导本身无害,但它的输出不应成为任何通知的唯一触发条件**;只能作为观测重叠的排序/折叠依据(内部量,不渲染)。作为独立特性,**推迟**。

### (c) 为 merge-back 裁决提供什么

- 分支生命周期内自身失效的前提数与清单 → D3 摘要行的"建立在 k 个已失效前提上"。
- 分支写集 ∩ 源线程读集 → 源线程的 premise_stale(已投递,merge-back 只引用)。
- 分支收到失效通知后的**反应**(下一轮是否重读)→ 分支结论是否"知情";这是 R3 之外唯一能对分支结论质量说话的执行事实。

### (d) 与 R9 的张力:分支间误报的下游自纠

- 单条误报:agent 多做一次 Read(一个 tool-call),发现无关,继续——路径存在,代价有界。与父线程今天的误报路径相同。
- 洪泛级误报:无自纠路径——agent 的注意力被 50 条通知稀释,不会"自己发现"这是噪声。所以 R9 在分支间的守法方式不是"更准",而是**每轮一束 + 家族折叠**(D4 失败 3)。
- 名义继承(盲区 8):无自纠路径——agent 对不属于自己的前提做出反应或不反应,都不产生纠正信号。只能前置检验。

### 为什么这不是编排器(R10)

机制里没有任何部件**分配工作、排序 agent、决定谁先跑、阻止谁跑**。它只让持有前提的一方知道前提变了;分支照旧自主决定读不读、改不改。唯一的阻断是封印点,而封印是每次 tool-call 的本地判断(hook),不是调度器,且 D4 给了它降级开关。判据:删掉整个机制,每个 agent 的行为空间不变,只是知道得更少——编排器被删掉会改变行为空间。

### 失效模式表(H1 专属)

| 情形 | 后果 | 处置 |
| --- | --- | --- |
| 子 agent 未继承上下文 | 100% 误报 | 不写 `footprint.inherited`(诚实开关) |
| 父线程曾压缩上下文 | 继承过期前提 | 引用窗口取耐久分层常数 |
| grep 洪泛 × 分支数 | 通知洪泛 | 每轮一束;耐久分层区分 grep |
| 父线程分叉点前已解决的失效 | 出生即收旧通知 | `refs` 展开取每路径最后观测 |
| 兄弟共享工作树同时写 | 封印抖动 | seal 模式开关 |
| 分支从无足迹前缀分叉(第 1 条消息) | 空读集,H1 无事可做 | 正常;不渲染 |

## D6 · Q4 恢复的双通道:叙事 + 仓库事实

### (a) 恢复卡信息架构

原则:**叙事是提醒,事实是分歧**。提醒在有笔记时总渲染("仅仅看得见就是提醒",挂起可见度 <25% 的证据);分歧只在非空时渲染("无分歧不渲染")。两者冲突时事实覆写叙事的**标注**,不覆写叙事的**文本**(R7:不破坏性替换)。

```
┌─ 你离开 41 分钟 · 3 条新消息 · 1 个分支有动静 · 前提 4/37 已变 ──────── [×] ─┐
│                                                                                  │
│  你在做   token 刷新改造(src/auth.ts, src/session.ts)                  ← 叙事拍  │
│  你决定   方案甲(拒绝了 2 条建议)                                 ← 账本(结构) │
│  下一步   跑 auth 集成测试 ⚠ 其前提已变                    ← 叙事拍 + 事实标注   │
│                                                                                  │
│  前提已变 (4)                                                     ← 事实段,可折  │
│    src/session.ts   被分支 C 改写      #4711  [diff]                              │
│    src/auth.ts      被你回滚到 h0      #4698  [diff]      ← 冲突规则 R3 命中      │
│    …及另 2 条                                                       [展开]        │
│                                                                                  │
│  分支动静 (1)                                              ← merge-back 一拍(D3) │
│    C(自 #5)· 选了 variant 2/3 · 写 session.ts · verified@cp-7  [打开][看改动][以 C 为主线] │
│                                                                                  │
│  前提监测:37 个 · 上次比对 3 分钟前 · 未覆盖:bash                ← 覆盖率行(D4 失败 4)│
└──────────────────────────────────────────────────────────────────────────────────┘
```

排列与折叠:
1. 头行永远一行;卡片可整体 dismiss(一次手势);dismiss 后侧栏保留一个小徽标(R7 退出对称:一键回来)。
2. 叙事拍(你在做 / 你决定 / 下一步)始终展开——它们是提醒,不是分歧;每拍带证据引用,无证据的拍不渲染(I7)。"脚下什么动了"这一拍**从叙事段移到事实段**——它在离开时是事实,在返回时必须重算,不能当叙事读。
3. 事实段默认展开前 3 条,余下折叠;为空时整段不渲染。
4. 分支动静段按 D3;为空不渲染。
5. 覆盖率行常驻——它是"沉默 ≠ 安全"的唯一防线。
6. R8:三个动作有标签——继续对话(直接打字,不设按钮)、`[看改动]`(代码)、`[打开分支]`(另一条对话);没有"恢复两者"按钮,卡片本身就是两者。

### (b) 冲突语义

**规则**:叙事永不被删,只被加注;事实永不被叙事覆盖;每条规则是 (拍的证据哈希, 当前哈希, 写者) → 标注 的纯函数,可单测。

| # | 叙事拍声称 | 仓库事实 | 谁赢 | 呈现 |
| --- | --- | --- | --- | --- |
| R1 | 写了 X(h1) | X 现为 h1 | 一致 | 原样 |
| R2 | 写了 X(h1) | X 现为 h2,写者 = 他人/分支 | 事实 | "写了 X → 之后被 C 改写 [diff]" |
| R3 | 写了 X(h1) | X 现为 h0(= 写前哈希) | 事实 | "写了 X → 已被回滚(写者 you/…)" |
| R4 | 写了 X | X 不存在 | 事实 | "写了 X → 已被删除" |
| R5 | 写了 X | X 被移动(导出面哈希匹配另一路径) | 事实 | "写了 X → 现在在 Y" |
| R6 | 决定了 D(账本) | 无仓库对应物 | 叙事 | 原样(账本是结构事实,不是文本) |
| R7 | 决定了 D;D 选的 variant 之后被撤销晋升 | 账本有 `promotion_reverted` | 事实 | "决定 D → 已撤销" |
| R8 | 下一步 N(启发式) | N 引用的文件任一命中 R2–R5 | 事实降级叙事 | "下一步 N ⚠ 其前提已变" |
| R9 | 任一拍 | 无证据哈希 | 无人 | **不渲染**该拍 |

需要补充:现有恢复笔记每拍是否已携带 evidence hash;若无,这是 H2 的前置(一行:起草时把用到的 footprint seq 写进拍)。

### (c) "你决定了什么"的升级路径:为什么放弃另一条

R1 下的候选信息源:

| 源 | R1 合规 | 成本 | 信息量 |
| --- | --- | --- | --- |
| 消息文本 | 否 | — | 高但禁用 |
| 用户手记 | 违 R2/R6 | 每次 | 不会有 |
| L3 N=2 重放 | 是 | 高;"走在证据前面" | 推测性 |
| 账本(选了哪个、拒了哪些建议) | 是 | 0(已有) | 低:只有编号 |
| **被放弃项的终态执行事实** | 是 | ~0(已有事件) | **中**:Verifier 裁决、失效前提、撤销事件 |

最大合法信息源是最后一行:"variant 1 测试失败 · variant 3 类型错误 · 你取了 2"——这是**被执行出来的理由**。没跑过 Verifier 的纯对话决定,理由在 R1 下不可得 ⇒ 不渲染 ⇒ 诚实。N=2 重放否决为源:它生产的是"如果当时选另一条会怎样"的推测,不是"当时为什么没选"的事实。

### (d) 退化情形:离开很久且仓库大变

- 触发:失效比例 >50% 或离开后 commit 数 >N(常数取 tribunal 的合并阈值风格,不新造)。
- 处置:事实段折为一行"仓库大变:23 次提交 · 91 文件 · 你的 19/37 前提已变 [看 diff]";叙事段加一行前缀"以下基于 9/1 的仓库";覆盖率行照常。**永不重算叙事**(R1)。
- 分支动静段不折——分支是少数。

### 验收句升级

现有:"隔天恢复无需翻 git log"。

升级:
1. "隔天恢复无需翻 git log;卡片上每条'动了'都能点到证据;卡片说'已比对的 N 个未变'的东西真的未变(精度 100%);卡片从不说'安全'。"
2. "若真变了而卡片没说,用户能在覆盖率行上 10 秒内看出那是盲区,而不是保证。"
3. fit 指标:两周内"返回后第一动作为 scroll-up / git log"的比例下降;恢复到首条消息的中位间隔不上升 >20%(否则 D4 失败 6 熔断)。

零新仪式:离开时不问、返回时不问;唯一手势是 dismiss。

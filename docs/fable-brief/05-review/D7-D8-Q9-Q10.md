## D7 · Q9 复核者 WIP

### 现状读数

- CONWIP 只 gate agent 派发;令牌数由 L=λW 从事件日志实测推导;`--force` 只留给人。
- 裁决队列:到达 0.75 条/h,上限 6,人类容量 ~1 条/10 分钟(≈6/h)⇒ 利用率约 12%【本机实测推导】。**人今天没有在裁决上饱和。**
- 人真正饱和的地方是**注意力**:多个未收尾线程/分支各有一个"下一步"——这是 T8/树熵的另一面,不是复核带宽。

所以"人是最终瓶颈"在两个不同意义上成立,处置完全不同:复核带宽(可测,进 Little's law)与注意力(不可测,只能可见化)。

### 干预点矩阵

| 干预点 | 家长式风险 | 可见 | 软提醒 | 硬 gate | 推荐 |
| --- | --- | --- | --- | --- | --- |
| 分叉手势 | **最高**:用户分叉常是为了逃离卡住的线程;此刻拦截 = 在最糟时机打断(+30% 恢复、2× 错误【文献】) | 侧栏"5 个未收尾分支"计数 | 无 | 否决 | 可见 |
| 新建线程 | 高:同上;且新聊天是 R6 用户的默认行为,gate 它等于 gate 产品入口 | 同上 | 无 | 否决 | 可见 |
| 派发(已有 gate) | 低:gate 的是机器 | 已有 | 已有(insufficient-history 明说) | **已有**;改进:让 W 含人类停留段 | 通过 Little's law 纳入人 |
| 裁决队列 | 低:pull-only,人自己拉 | 已有(上限 6) | 上限即提醒 | 已有 | 不动 |
| 恢复时刻 | 中:卡片已是加法式 | 覆盖率行 | 无 | 否决 | 不动 |
| **verified 未处置的 checkpoint** | 低 | **新增计数**"3 个已验证等你处置 >24h" | 无 | 否决 | 可见 |

### 推荐:否决对人类手势的任何 gate;让人的带宽通过测量进入机器的 gate

- **机制**:WIP 派生的 W 若尚未包含"checkpoint verified → 人类处置(merge/adopt/dismiss)"的停留段,把它加进去(需要补充:当前 W 的起止事件)。人越慢,W 越长,令牌越少,agent 派发自动收紧——**人的带宽 gate 了机器,而不是机器 gate 了人**。这是 R10 合规的唯一形态:调度器约束的对象永远是 agent。
- **可见化**:两个计数,侧栏常驻、可 dismiss:"未收尾分支 N"、"已验证待处置 M(最久 3 天)"。加法式、空态不渲染。
- **不做**:软提醒("你已经开了 5 个线程了")——这就是 R5 的提议 UI 变体,提议区间为空。

### 若有人坚持硬 gate(不推荐)的退化条款

只允许 gate **自动**派发(调度器)——本来就有;人类 `--force` 永远通过。退化为软提醒的条件:insufficient-history(完成样本 <3)时不得用人类段推导,退回物理上限(现有行为)。永久关闭:配置一行,退出与进入对称(R7)。

### 自由放任的可观测风险

| 风险 | 观测量 | 处置 |
| --- | --- | --- |
| 已验证 checkpoint 堆积、agent 继续产出无人看的东西 | verified 状态 >24h 的数量(现有状态 + 时间戳) | 计数可见;W 纳入后自动收紧派发 |
| 分支蔓延 | D4 失败 2 | 侧栏折叠 |
| 裁决队列逼近 6 | 现有 | 现有上限 |
| 人被通知洪泛(不是 WIP 问题) | D4 失败 3 | 每轮一束 |

### 否决论证

gate 人类手势违反 R5(提议区间空)、R7(退出不对称:被拦的分叉没法"撤销一次拦截")、R12(拦截本身零成本但其代价是打断,打断代价 >K)。legacy 的"the limit is your review bandwidth"是真的,但它推出的是"少派发",不是"少分叉"——分叉不产生复核负担,派发才产生。

## D8 · Q10 chat/world 边界的终态

### 判断:统一日志,不统一语义;"翻译层 vs 统一流"是伪二选一

翻译层做的事——在查询时把两个存储按 (actor, subject, 时间) join——就是投影。区别只在 join key 是否可靠:两个存储两个时钟,join 靠 `ts`(墙钟,不可靠);一个日志一个 `seq`,join 靠因果。所以终态是 D2:**一个 seq 空间 + I3/I4 方向性不变量**。TF-0118 的顾虑安置在 I3(调度投影过滤器),不是删掉。

### 统一后可执行的新查询(每条 = 省掉人的一次什么动作)

| # | 查询 | 省掉的动作 | 需要的 join |
| --- | --- | --- | --- |
| 1 | 我刚才这次 commit 让哪些分支/线程的前提失效了? | 逐个打开分支重读 | `promote.signal{commit}` × `footprint.inherited` × `premise_stale` |
| 2 | `src/auth.ts` 最后一次是哪个线程、在哪条决定下写的? | `git blame` + 翻线程找那一轮 | `footprint.generated{actor}` × `variant.promoted`/`suggestion.taken`(账本) |
| 3 | 我离开后哪些改动碰了**这条对话**读过的东西?(R2′) | `git log` + 脑内过滤 37 个文件 | `thread.restored.since_seq` × footprint × 世界写 |
| 4 | 哪些分支的结论建立在已失效前提上且未经 Verifier? | 重跑测试 / 重读分支 | `thread.forked` × `premise_stale{target}` × `tribunal.verdict` |
| 5 | 这条决定(账本条目)之后接口注册表变了几个版本? | 翻注册表 + 对时间 | 账本 seq × `iface.drift`(seq 区间) |
| 6 | 封印在过去一小时封了谁、依据哪条漂移? | 无法回答(现状封印不持久化) | `seal.decided.drift_refs` |

六条都能写成 `fold(log)`;没有一条需要文本(I6)。**统一不是伪需求**——但注意 6 条里 4 条是并发投影的查询,只有 1、4 真正依赖树事件。这再次印证 D1:树的价值是作为前提账本的**账户结构**,不是作为导航对象。

### 什么必须不统一

| 不统一项 | 理由 | 安置 |
| --- | --- | --- |
| 调度语义(线程不消耗令牌、不进裁决队列) | 否则 fork 扇出吃光 CONWIP;R10 | I3 |
| 真相语义(线程的 generated 是写事实;线程的"说"不是任何事实) | R3 | I5 schema 校验 |
| 通知预算(tribunal 五道门 vs chat 每轮一束) | 两个消费者节奏不同 | 两个投影两个预算 |
| 文本 | R1 | I6:正文永不进 events.jsonl |
| 衰减函数(前提按世界变;DOI 按时间/生命周期) | 不同投影 | 各自 fold |

### 对 R3 的影响(必须讨论)

统一日志的诱惑是"线程 tool-call 跑了 `npm test` 且 exit 0 ⇒ 完成"。三道防线:
1. **schema**:`source: sessions` / `actor.type: thread` 的事件无状态字段(I5)。
2. **投影**:只有 `actor.type: verifier` 的 `verdict` 能进"verified"投影;线程内 agent 自己跑的测试是 `footprint`(它读了输出),不是 verdict。
3. **渲染**:D3 验收 3——无 verdict 则串含"未经 Verifier"。

反向影响(有益):Verifier 的裁决现在能 `refs` 到它验证的是哪条线程/分支的哪个 checkpoint——"agent 自称完成不可信"从原则变成可查询事实:`claims without verdict` 是一个 fold。

### 迁移路径(R11)

D2 的 7 步。额外一条:**chat 层 HTTP 端点是唯一入口**(CLI 无 tree/fork 命令)——迁移不要求加 CLI 命令;但 `stats`/查询 fold 应当是 CLI 命令(它们是只读投影,符合"CLI + 文件系统"的产品形态,且是 D1 E3 的载体)。

### 两难陈述(不可消除)

"a thread is not a lane"守住了 R10,但 R2′/H1 要求线程是**一等读者**——读者需要被通知,通知需要预算,预算需要队列,队列就是 tribunal 的形状。**要么给 chat 层复制一套 ISA-18.2 纪律(代码重复、两套常数),要么让 chat 投递复用 tribunal 的队列但不占其配额(一个队列、两个预算域)。** 触发条件:第一次三路分叉。前者代价是两套常数漂移;后者代价是 tribunal 代码开始知道"线程"的存在(I3 的边缘)。我倾向后者,但边界要写成一句话:"tribunal 队列可以承载线程投递,tribunal 配额永不计线程"。

## D13 · 自我审计:最弱一环与最强反驳

**最弱一环**:D1/D0 的核心判断——"§3.5 的证据全部关于线性恢复,零条关于分叉,所以树是错误重建"。

**最强反驳**(150 字):Dow 平行原型(44 vs 26 真实点击)恰恰是关于*并行备选*的证据,而 generate-N-show-1 + 账本本身就是一棵树;ChatGPT 235 条投诉证明用户确实在版本间导航;Claude Code 上线 `/fork` 与 #32631 完整规格是平台重度用户的需求证据——而单人项目的 n=1 用户正是重度用户,R6 的"中位用户"论证对他不适用。因此"零条关于分叉"是选择性阅读:我把空间备选的证据全部记在了"非树"一栏。

**若此反驳成立,要改的结论**:D1 的砍留从"树导航/merge-back 摘要级默认砍"软化为"树导航最小形态(侧栏缩进)进 W7、merge-back L1 不设门 #1";D10 的 W6 门保留但阈值从 1/周降到 1/两周;D11 的"时间分叉是证据最弱的特性"改为"证据次弱"。**不会改的**:R2′ 第一(它与树不冲突)、L3 死、内容级合并死、"前提守护"命名、D2 的方向性不变量、D4 全部熔断、D0 盲区。

第二弱一环:D2 的 I4("世界事件永不引用会话事件")可能过严——merge-guard 若知道两个写者是同一 fork 家族的兄弟,重叠预测精度会提高。若接受此反驳,I4 放宽为"世界投影可读会话事件作**先验**,永不作**事实**",I3 不变。

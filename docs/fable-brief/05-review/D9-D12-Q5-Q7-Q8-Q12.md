## D9 · Q5 隐式→显式升级判据与树的清理学

### Mylyn 信号面迁到 chat 语料

| Mylyn 信号 | chat 对应 | 采集点 | 噪声 | R1 合规 |
| --- | --- | --- | --- | --- |
| selection | 切换到线程 | 切换处理器(已有清场钩子) | 中(误点、浏览) | 是(UI 事件) |
| selection | 停留 | focus/blur 时间戳 | **高**(挂机、切窗) | 是 |
| selection | 引用 | composer 的 @文件 / 引用消息 UI | 低但稀 | **是,仅当它是 UI 手势**;从正文里认 `@file` 是 R1 违反 |
| edit | agent tool-call 读/写 | footprint | 中(grep 洪泛) | 是 |
| — | 复活(>1 天后返回) | `thread.restored` | 低 | 是 |
| — | 确认(plan 批准、建议采纳、晋升) | 账本 | **最低,最强** | 是 |
| — | 撤销 | `*_dismissed/_reverted` | 0% 误报【文献】 | 是 |

可执行:是,且 6 字段模型已存在(需要补充字段)。但**第一个消费者不该是树修剪**。

### 第一个消费者:恢复卡内的排序

L1 值得接电的条件是"有一个高频、加法式、容忍 28% 错误、无人需要批准"的消费者——那是 Mylyn 的胜利条件。树修剪是低频(分支少)、且"近期 + 有无账本"两特征已足够。**恢复卡里 37 个失效前提怎么排序**才是高频消费者:DOI 高(最近被 agent 写过、被用户引用过、在被晋升的 variant 里)的前提排前。排错的代价是用户多扫一行——Mylyn 式无害。

### 树修剪的杀死判据

H3 通过当且仅当:对照实验中 DOI 折叠比"近期 + 有账本"折叠让用户少展开一次。我的预测【推断】:不会——分支数量级太小,两特征已饱和。**否决 H3 作为 L1 的接电理由;修剪用近期规则。**

### L3 的 N=2 升级判据

三条同时满足 4 周:(1) 分叉 ≥1/周;(2) ≥30% 分叉家族出现兄弟交替(D1 E2);(3) 账本中 `promotion_reverted` ≥1/周(单展示 variant 错得足够频繁,才值得展示两个)。三条中任一不满足,L3 不动。"逐字面量拒绝"的含义需要补充,无法评估。

## D11 · Q8 命名与哲学框架

| 框架 | 一句话公理 | 自然推出 | 禁止 | 最易滑向的堕落版本 |
| --- | --- | --- | --- | --- |
| **前提守护 / Premise Custody** | 对话持有前提;世界改变前提;工具唯一职责是让持有者知道前提何时不再成立 | R1(前提来自读,不来自话)、R2、R3(完成是关于世界的前提 → Verifier)、R4(守护告知不阻断)、R9(误报耗注意力,漏报下游自纠)、R10(守护 ≠ 编排);fork = 前提快照、restore = 前提重核、merge-back = 因兄弟倒下的前提清单、DOI = 哪些前提最重要 | 路由工作、合并内容、推断意图、gate 人 | **前提警察**:封印长成 lint 门,每次写都被拦——T6 的例外吞掉规则 |
| 执行即真相 / Trace Is Truth | 结构只从已发生的执行读出;说过的话不是结构 | R1、R2、R3、R8(对话与代码是两条不同的轨迹) | 文本挖掘、用户画图 | **日志崇拜**:日志成了产品,仪表盘无人看——35 年坟场的另一面 |
| 时间分叉 / Temporal Forking | 决定是时间线上的分叉点;树是决定的证据,不是窗口的排列 | 血统、账本、adopt | 空间复制作为主隐喻(Nimbalyst) | **分支迷宫**:无人导航的树;ChatGPT 删掉的箭头 |
| 加法式户籍 / Additive Registry(v3) | 每个写者都登记;登记只增不删;没人需要批准登记 | R4、R7、R9、R12(Mylyn 条件:没有东西依赖它正确) | 破坏性自适应、批准 UI | **无人读的户口本** |
| 注意力维护 / Attention Maintenance | 瓶颈是人的注意力与前提,不是 agent 调度;每个部件必须能证明它减少了人要看的东西 | R5、R6、R7、R10、R12 | gate 人、编排 | **自动隐藏一切**:沉默伪装安全(D4 失败 4) |

**只留一个:前提守护(Premise Custody)。** 理由:它是唯一一个让三支柱都成为**实例**而非并列部件的公理——分叉是前提快照,恢复是前提重核,通知是前提变化,DOI 是前提排序;它直接推出 R1–R4、R9、R10 六条红线,经"守护必须廉价到可以无视"推出 R5/R7/R12;它说的是产品**做什么**(你会知道你相信的东西何时不再为真),其余四个说的是产品**是什么**或**怎么做**。它就是 v5 的名字——**v6 不是新身份,是 v5 的 UI 推论**;T1 的身份断裂由此弥合,不需要第七版定位。

其余该死的原因:执行即真相是认识论,不是产品;时间分叉是特性,而且是证据最弱的那一个;加法式户籍是存储纪律;注意力维护是设计约束——四个都活着,作为推论。要盯的堕落:封印。守护者变警察只需要把 `warn` 的默认改成 `block` 再多加两个触发条件。

# D1 · Q0 攻击前提

根命题:"单会话线性交互结构性地丢失试错历史与决策理由,且这个损失大到值得为其重建交互模型。"

先拆开它的两个子句,因为它们的证据状况完全不同:
- **子句 A(丢失)**:线性会话丢失历史与理由。
- **子句 B(值得)**:损失大到值得重建交互模型(树 + 分叉 + merge-back + L1–L3)。

三支柱对这两个子句的暴露度不同:**并发支柱对两者都不依赖**(它的命题是 v5"对手是时间,写者 ≥2");**会话树的 fork/merge-back/树导航半边完全押在 B 上**;**会话树的恢复半边与 L2 的清场/停放只依赖 A**;L3 押 B 且自评"最容易砍"。所以"攻击根命题"实际威胁的是:fork/merge-back/树导航、L3、H3/H4/H6 中的树专属部分。其余部件即使根命题倒了也应留下。

## 总判

- **子句 A 成立**,而且是三支柱里证据等级最高的部分;但成立的形式是"丢失前提与恢复语境",不是"丢失决策拓扑"。
- **子句 B 未证**,且其两个最强反证(R1 悖论、平台从上面关闭空白)不需要任何实验就已经站得住;实验只是量化。
- **结构性结论**:把"会话树"从支柱降为**前提账本里的一种账户结构**(fork = 新账户继承前提;restore = 账户重核;merge-back = 因兄弟而倒下的前提清单)。这样树的每一部分都能被 R2′ 的证据链背书,而不用背一个自己背不起的"保留理由"承诺。命名上的推论见 D11 Q8。
- **委托方最大的心病**(117/119 fit unknown)在这里有最直接的一次成像:证伪线"每周岔开 <1 次"的数据(`meta.forks`)已经存在,却从未被读过。E3 是半天的事。

## 实验组合的判决矩阵

| E1 理由可重建 | E2 兄弟交替 | E3 分叉/周 | 判决 |
| --- | --- | --- | --- |
| 低 | 0 | <1 | 树整体降级为"带前缀的新线程";全部资源转 R2′ + 恢复卡 |
| 低 | 0 | ≥1 | 用户在用 fork 当"新聊天+上下文";建 H1(继承读集)但不建 merge-back 摘要、不建树导航 |
| 高 | >0 | ≥1 | 树有真实比较行为;按 D3 建 merge-back 一行摘要 + "以分支为主线";树导航仍等第二个门 |
| 高 | 0 | 任意 | 理由能从执行重建,但没人比较——建"被放弃分支终态"进恢复卡即可,不建树 |

## D0 · 决策摘要

### ① 最重要的三个判断

**1. 根命题半真:线性交互丢的是"前提与恢复语境",不是"决策拓扑";树是对正确损失的错误重建。**
依据:§3.5 中所有带 p 值或 n 的效应量(Mylyn p=0.003、TaskSnap n=55、Leroy & Glomb、ConE 26000 PR、CoAgent 1.4×)全部关于**恢复、聚焦、通知**,零条关于分叉;ChatGPT 的 235 条投诉是"编辑版本找不回"(带编辑的线性),不是树导航。更根本的是 R1 使"为什么放弃另一条"在宪法上不可捕获——R1 合规的树只能存"选了什么"(账本),而"选了什么"git 已经存。正确的重建是 R2′(恢复时读集 diff),它才是三支柱里唯一不被 git 和 Claude Code 原生 `/fork` 覆盖的东西。【推断】

**2. 三支柱是"一条日志、两类事实、三个投影",不是一层也不是三层。**
世界事实(footprint / verifier / git,单调)与会话事实(fork / leave / restore / merge-back)可以共享同一 `seq` 因果钟,但世界投影(前提、merge-guard、CAS)绝不能读会话事件——TF-0118 "a thread is not a lane" 是**投影过滤器**,不是存储边界。因此 H1 必须以 `footprint.inherited`(一条世界事件,`refs` 指向父线程足迹)实现,而不是让前提投影去读 `thread.forked`。R3 用 schema 强制:`source: sessions` 的事件没有任何可携带"完成"的字段。【推断】

**3. merge-back 的最小正确语义是"恢复卡上的分支节拍",不是独立动作。**
指针 + 一行结构摘要(账本差 / 写集 / 接口版本变化 / merge-guard 预测 / Verifier 状态,每项带 `seq` 溯源),触发点 = 用户回到源线程的那一刻(R5:不问"要不要合并");内容级合并砍掉(LLM 语义合并 55–59% = 掷硬币,且模型读过即不可撤销);唯一新增显式手势是"以分支为主线"(改身份不改内容,一次 undo)。与 H5 的差别:H5 没定义触发点、没有"无分歧不渲染"门、没有 Verifier 状态、把叙事放在了事实前面。【推断】

### ② 最危险的一个盲区

**分叉子线程是 `freshAgentSession`——如果模型上下文没有继承(非 `--fork-session` / 非重放),那么 H1 从继承前缀合成的读集,是子线程 agent 从未读过的前提。** 分支间的每一条 premise_stale 按构造都是误报(R9 反向),而"分支作为读者/写者"(H1)、"分支间通知"(T5)、"恢复卡分支节拍"(H2/H5)全部建立其上。这是全评审里最便宜的检验:分叉后问子线程"我们刚才讨论到哪了"——10 分钟出结果。需要补充:`freshAgentSession` 的继承机制。【你的假设】

### ③ 若只能做一件事

**做 R2′:恢复时对线程读集做 diff,渲染为只含事实的恢复卡。** 理由:(a) 它是唯一不被 git、不被 Claude Code 原生 fork 覆盖的能力——git 给你 37 个文件变了,R2′ 告诉你其中哪 4 个是*这场对话*的前提;(b) 证据链最强(ConE 3%/70% + Leroy & Glomb 2× + "挂起工作可见度 <25%");(c) 复用 premises.ts / footprint,≤1 周;(d) 不依赖树假设,树被砍它也活;(e) 它的使用日志(返回后第一动作是否仍是 scroll-up / git log)同时是"树该不该建"的测量仪。

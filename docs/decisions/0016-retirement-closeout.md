# ADR-0016：退役后构建依赖、归属与入口收口

- 状态：已接受（2026-09-21，用户授权完成决策并修复现存问题）
- 森林节点：TF-0225（退役执行）、TF-0226（夹具迁移），上级目标 TF-0176
- 补充：[ADR-0015](0015-legacy-retirement-execution.md)；纠正 [ADR-0013](0013-workbench-identity-and-compliance.md) 之后已变化的归属范围，不改写历史决策

## 问题

退役提交后的现有工作区通过了 904 + 61 + 65 项测试，但这不足以证明全新安装可构建：
`apps/workbench-ui/src/index.css` 仍引用 Geist 与 Geist Mono，根依赖删除时没有把它们迁入
面板包，锁文件也没有这两个包。仓库外的临时目录仅复制当前清单与面板源码，执行
`bun install --frozen-lockfile --ignore-scripts` 成功，再执行面板 `bun run build` 则退出 1，
报 `Can't resolve '@fontsource-variable/geist-mono'`。原工作区残留的字体目录掩盖了错误。

此外，待应用的退役提案把依赖方向写反；根 README 仍以旧产品介绍为主体；根 NOTICE
仍宣称打包已退役组件；包 NOTICE 的“除主题外全部原创”也遗漏了已移植的权限提示和流夹具。

## 决策

1. **依赖归消费者所有。** 将退役前实际使用的 Geist 5.2.9 / Geist Mono 5.2.8 固定在面板包并更新锁文件，
   Workbench 的四个运行时依赖保持原有范围。CI 的面板测试后执行真实 UI 构建，覆盖
   TypeScript 与 jsdom 不会检查的 CSS 导入。根 `build:ui` 只调用一次已有构建入口，
   避免 Vite 重复构建；发布测试沿用包声明的测试入口与超时。
2. **首页只描述当前产品。** 根 README 提供 Workbench 的使用、开发与发行物验证入口；
   旧 Helmor 的完整介绍留在 Git 历史，当前页只保留退役说明与 ADR 链接。
3. **保留归属，修正范围。** 根 NOTICE 保留上游版权、Apache-2.0 与商标声明，将当前组件
   清单指向随发行物分发的包 NOTICE。补登记权限提示的 TypeScript 移植及 49 个原样迁移
   的流夹具，并在相应源码处补来源说明；夹具仅用于源码与测试，不计入运行时发行物。
4. **按真实顺序登记。** 修正既有提案为“删除执行依赖夹具迁移”，补登记 TF-0225 / TF-0226，
   在本轮门禁通过后收口 TF-0176 的旧手工进度。保持已完成的子任务历史与外部阻塞事实。
5. **此次完成本地验收。** 暂不推送 main 或创建发布 tag；远端 CI 与跨平台发行不由本机
   检查代替。

## 验证方式

- 在仓库外安装冻结锁文件并构建，避免解析到工作区残留的依赖；修复前后使用同一隔离目录。
- 三包 typecheck、Biome 与三套测试，以及 UI 构建、二进制 / JS 两种产物的 `test:build`。
- 检查 dist 中的归属文件与包内文件一致，流夹具与迁移前 Git blob 一致。
- 任务森林通过 CLI 保存和应用修正后的提案，再校验并导出；不手写权威图或重写事件。

本轮结果与可复跑命令记在 [验收记录](../retirement-closeout-validation-2026-09-21.md)。

## 补记（2026-09-23）：退役范围漏掉了 `docs/user/`

[ADR-0015](0015-legacy-retirement-execution.md) 的执行表逐项清理了代码、构建、CI 与配置，但**从未覆盖 `docs/`**；TF-0238 清理 Helmor 残留时的 grep 也**明确把 `docs/` 排除在外**（理由是把 docs 当作不可改的历史记录）。结果是 `docs/user/` 下 19 个文件的**旧 Helmor 桌面应用用户指南**在退役后一直留在工作树里，仓库里没有任何活引用指向它。

处理决定（2026-09-23，用户选择）：**保留，但加退役声明**。它是「旧产品对用户承诺了什么」的一手记录，被吸收叙事引用（见 [fable-brief/03](../fable-brief/03-deep-state-appendix.md)）；删掉它，这份记录就只剩 git 历史可查。已在 `docs/user/README.md` 顶部加完整声明，并在其余 18 个分页文件顶部各加一行同义提示——否则从搜索直接落到某一页的读者仍会把它读成本仓库的功能说明。

**教训**：退役执行表是按「引用面」枚举的（样式、构建、发布、CI），而文档不在任何引用面上，所以枚举不到。下次做同类清理时，**文档目录要单独过一遍**，不能只靠「有没有代码引用我」。

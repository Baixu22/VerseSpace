# ADR-0025：声明范围的验证与单产物重验

- 状态：已接受（2026-10-01，维护者要求修复全部开放 issue）
- 扩展 ADR-0010 的世界事实投影；仅对 issues #50–#54 指定的纵向切片放开 ADR-0023 的功能冻结。ADR-0024 的退役范围不变。
- 追踪：GitHub #49–#57；不在本轮改写本机任务森林。

## 问题与决定

退出码只能证明命令的退出结果，不能证明声明的用例都运行过。文件重读也不能证明依赖它的产物已适应新版本。新增能力限于单仓、显式声明的文件输入、一个产物和一组检查，沿用 Blackboard、checkpoint、CLI JSON 与只读恢复投影。

1. 选择已有 Vitest JSON reporter 格式。验证可声明报告路径、非空用例 fullName 集合及非敏感文件输入。记录实际用例、通过/失败/跳过数量、报告 hash、命令退出码与来源；集合必须完全一致且全部通过。零用例、缺失、损坏、重复用例名或未更新的旧报告均不能签发范围满足。未声明范围的旧检查仍保留其退出码语义，范围明确未知。
2. 绑定显式文件输入的内容 hash（包括被 Git 忽略的配置）和执行 Workbench 的运行时版本。仅保存 hash，不保存配置值。不声称覆盖外部服务、隐含环境变量、子进程实际工具链或原子快照。验证报告自身是输出，从代码绑定中精确排除，不扩大到整个目录。
3. 单产物关系必须由调用者声明。结构/先读后写只能作为候选，不自动升级为因果。产物的历史验证保留，当前输入变化产生独立待重验状态。重验生成新的 checkpoint 证据，禁止重放旧 blackboard effects；无需改代码但检查通过也是有效结论。
4. 记录形成证据时的仓库、工位、输入/产物版本和显式目标 ref/base。工位内容相同不能代替目标主线当前可用；缺失身份或目标不可读取记未知。新读取不能覆盖旧产物来源。
5. 通知的旧 repaired 指标维持兼容。新增证据分别表示重读、新版本观察、产物修改和声明范围验证，明确它们可重叠且不是修复正确率。

## 验收与边界

使用 Windows 隔离仓库及真实验证子进程检验：退出成功但零用例/子集/坏报告、配置变化、跨文件输入变化、复读未修、失败与无需修改的重验、applied 后失效且 effects 不重放、跨工位和目标主线推进。正常通过必须保留对照，CLI JSON/MCP/恢复卡必须可以追溯证据。

性能先测量日志规模、冷/热应用读取与分布再决定优化，不引入数据库、通用依赖推理、任意 Shell 解析器、自动合并或新看板。合成、真实 HTTP、真实 CLI 读数分别记录；不把退出 0 或接受覆盖限制升级为完整产品保证。

# ADR-0006：并发控制采用建议式（advisory），拒绝 single-writer 排他

- 状态：由 [ADR-0010](./0010-premise-custody.md) 收敛；下文保留历史提案
- 日期：2026-08-29，**2026-08-30 依第二轮调研重写**
- 相关：[`positioning-v5.md`](../positioning-v5.md) §6 · ADR-0007（单调优先）

现行决策：建议式通知与显式封印点保留，通道采用持久队列 + stdin。
下文的跨会话 socket、通用 saga 与全局可串行化承诺不再是实施要求，具体边界以 ADR-0010 为准。

## 背景

多个写者（agent 会话、人的编辑器、`git pull`、CI 提交、同一会话的前一次运行）同时作用于一个仓库时，属于经典并发控制的领域，但经典机制在 agent 场景下失配，原因有二：

1. **一次 agent「事务」跨越数分钟推理**，而经典协议假设事务与重试都便宜。
2. **读集宽而不透明**（agent 会 grep 整个仓库），且外部状态无法 fork 或缓冲——写一旦执行即刻生效。

实测数据（CoAgent，arXiv:2606.15376，十个竞争负载）：

| 方案 | 结果 |
| --- | --- |
| 无协调并行 | 快，但**通过率仅 13%** |
| 2PL（悲观锁） | 每轮死锁 0.81 次，加速比 **1.04×**（几乎无收益） |
| OCC（乐观回滚重试） | 每轮回滚 0.95 次，**0.93×（比串行更慢）**，token 成本 1.83× |
| MTPO（建议式通知 + 选择性修补） | **1.4× 加速，正确性与串行相差 ≤5%**，token 1.15× |

旁证：Chroma Fission 的 git 原型中 **8 次调用有 4 次放弃**——"因为读已过时，或要写就必须重读，因为别人在它底下写了"。即**悲观锁死锁、乐观重试放弃一半**，两条经典路线在 agent 时间尺度上都不可用。

另一方向的已有工作 **agent-coherence**（arXiv:2603.15183）把 MESI 缓存一致性协议搬到共享 agent 产物上，用 TLA+ 验证了三个不变量（single-writer safety / monotonic versioning / bounded staleness）。其 MESI Modified 态即排他所有权，属 single-writer、fail-closed 姿态；其目标函数是**降低同步 token 成本**（报出节省 84–95%），正确性为搭车副产品；评估为仿真，集成面为 LangGraph/CrewAI/AutoGen 进程内 agent。**它明确声明"每个 agent 有自己的 worktree 就不需要它"——而那正是 CoAgent 证明不成立的那句话。**

写集分区（git worktree、Claude Code agent teams 的提示词纪律）不能解决问题。CoAgent 原话：**"Partitioning constrains writes; the bug is in reads."** 竞品核实（13 个产品，2026-08）确认：**无一实现预冲突检测，全部只在 merge 时才知道。**

同构佐证：GraalVM Truffle 的 `Assumption` API 是生产级的假设-依赖注册表（编译代码注册假设，`invalidate()` 使全部依赖代码失效）；Deoptless（PLDI 2022）把"去优化到解释器"（= OCC 全量重试）改进为"跳出失败假设的同时跳进针对新事实特化的版本"（= 选择性修补）；CoreJIT 是形式化验证过的推测+去优化编译器。**数据库并发控制、分布式系统、缓存一致性、编译器推测执行四个独立领域收敛到同一结构。**

## 决策

采用**建议式并发控制**：**runtime 通知，写者修补。**

### 1. 采纳

1. **乐观姿态**：任何写者在任何时刻都不被阻塞，也不被整体回滚重试。
2. **写立即生效**：不假设存在私有缓冲或可 fork 的状态。
3. **读集追踪**：每个写者记录 `observed: Record<key, version>` 与足迹 `used:[{path,hash}]`。
4. **失效通知**：reconciliation 循环发现活跃写者的读集与现值不符时，投递带 diff 的通知，由 **LLM 自行判断该冲突是否推翻其计划前提**，并**只修补依赖失效值的那几步**。
5. **saga 式补偿**：需重排的写通过预先登记的逆操作机械撤销与重放；步骤分类 compensatable / pivot / retriable，pivot（`git push`、`gh pr create`、任何网络写）之前只放 compensatable。
6. 从 agent-coherence 的 TLA+ 规格**继承两个不变量**：**monotonic versioning**（`RegistryEntry.version` 已是此形状，改为写前置条件）、**bounded staleness**（作为对外声明的隔离级别）。

### 2. 读集的真正作用：基率放大器（第二轮新增，最重要）

`PPV = pH / (pH + (1−p)F)`。基率 p=2%、召回 90%、误报率 10% 时 **84.5% 的告警是假的**；要 PPV≥0.70 需误报率 ≤0.79%（d′≈3.7），近乎完美的检测器。

> **可行的动作不是造更好的分类器，而是提高 p：只考虑「与已记录的同一符号读取相重叠」的写。** 这把有效基率抬进 10–30% 区间，同一检测器即给出 PPV 0.5–0.8。

**记录读集的首要理由不是审计或治理，而是让告警在数学上可能成立。** 这条决定了读集是必需品而非增强项。

### 3. 两个阈值，不是一个（第二轮新增）

决策论切点 `θ* = C_FA / (C_FA + C_M)`：

- **面向 agent：θ ≈ 0.10，激进通知。** C_M 巨大（无协调通过率 13%），C_FA 只是一次额外推理且**被通知 agent 误判相关性的比例仅 5%**。**agent 是便宜且校准良好的第二级过滤器——这正是把 LLM 放在回路里的意义。**
- **面向人：θ ≥ 0.70**（Wickens & Dixon 荟萃分析：可靠性 0.70 是"不如没有自动化"的临界点），**0.30 以下不发**，且**聚合后再发**。

### 4. 人类通道：二元 + 保守门槛，拒绝分级（第二轮新增，推翻初稿）

- **Zirk, Wiczorek & Manzey (2020)**：联合人机灵敏度 **保守二元 > 4级 LAS > 3级 LAS > 自由二元**；**漏报上保守二元显著优于其余全部**；**保守二元无狼来了效应**。应用建议逐字："implementing conservative BASs in multi-task working environments."
- **Wickens & Colcombe (2007)** 摘要逐字："there was no benefit to a three-level system over a two-level system"，且实测有代价。
- **决定性边界条件**：Wiczorek/Balaud/Manzey (2015) —— **能核验告警有效性时 LAS 优势消失**，而本场景**永远能核验**（随时可看 diff）。

低于门槛的内容**不是第二个告警级别**，而是在自然边界主动**拉取**的软摘要。**推送通道保持二元。**

### 5. 投递时机（第二轮新增）

**在写者的下一个工具调用边界投递，绝不在推理中途。** 依据：MTPO 的可串行化论证依赖**单向（低序→高序）**投递（双向重新引入环）；Iqbal & Bailey 实测断点投递**降低挫败感 20%、反应时间 25%**；LLM agent 在工具结果边界工作状态已外化，**恢复延迟≈0**。

**唯一例外：若下一个调用正是写入失效区域，则同步阻塞——那不是打断，那是封印点。**

机制为 `CLAUDE_CODE_MESSAGING_SOCKET`（**在活跃轮次的工具调用之间投递**），且**只追加**，落在 KV 缓存安全一侧。

### 6. 拒绝

- **single-writer safety / 排他所有权 / 文件租约**。长推理下排他所有权退化为 2PL（1.04× 加速、死锁常态化）。已有两个小项目走此路线（Claudio `internal/filelock/`、forge-orchestrator `.forge/locks/`），作为反面参照。
- **fail-closed 拒绝写**。写者无法从被拒绝中恢复，等价于 OCC 整体重试。
- **CRDT 合并源码**。CRDT 买的是收敛不是正确性；跨对象不变量证明上需要协调；文本 CRDT 会收敛成语法正确但编译不过的代码。
- **分级 / 似然告警**（人类通道）。见第 4 条。
- **Chandy-Lamport 全局快照**。约束是 FIFO 通道；写者一旦绕过中介即得到不一致切分。预分配序 + 每对象版本轨迹已足够。

### 7. 声明的正确性目标与边界

在 runtime **可观测的文件范围内**追求**可串行化**。**明确不覆盖**：runtime 观测不到的外部副作用（网络写、外部服务状态）、以及**只改方法体的语义变化**（改默认值、翻布尔、收紧校验、换异常类型）——所有 ABI 式谓词按构造对此盲，**这是已接受并记录在案的空洞，不是待修 bug**。

### 8. 产品承诺红线

Meyer 的依从/信赖区分 + Gérard & Manzey 基准（PPV .9→.7 依从掉约 25%；NPV .98→.93 信赖掉约 25%，**信赖脆弱得不成比例**）：

> **争取依从，不争取信赖。** 承诺是"**我说话的时候，你信我**"，**绝不是**"我没说话你就安全"。**永远不要把沉默包装成安全保证。**

## 后果

**正面**

- 得到**可测试的正确性属性**（可串行化）而非口号；隔离级别可对外声明。
- 与"对话即引擎"一致：判断与修补由 LLM 承担，runtime 只做记账与通知——与现有 automaton 纯函数 + reconciliation 循环形状天然契合。
- 差异化落在读侧，而竞品全员在写侧且只在 merge 时才知道。
- 继承已发表的 TLA+ 不变量两条，减少自行发明的风险面。

**负面 / 风险**

- **正确性依赖 LLM 判断**：低价模型上 5% 误判率。必须保留 human-review 兜底，且误判需可审计。
- **投递依赖引擎能力**：`CLAUDE_CODE_MESSAGING_SOCKET` 在原生 Windows 需 CLI ≥ 2.1.234；**WSL2 ↔ 原生 Windows、宿主 ↔ 容器互相不可达**。二元风险，须在 Sprint 0 用最小连通性验证打掉。
- **只有具备工具调用的提供商可参与**：现有四提供商中三个 HTTP 纯文本路径产不出读写集，须降级或裁撤。
- **逆操作覆盖率有限**：存在不可补偿动作（已 push、已合并、已发出的评论、已删除）。必须显式枚举 pivot 并禁止其出现在 saga 中段。
- **误报的代价会复利**：消耗最稀缺的资源（上下文）并教会人静音通道，**一旦静音有效召回归零**。而漏报是**自纠正的**（类型检查/测试/复核在下游抓住）。**故往精度错，不往召回错**——这与构建系统/TIA 的默认取向相反，因为它们的漏报模式是静默损坏，我们的不是。

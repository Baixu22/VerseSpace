# ADR-0009：实测 B/C/K——提议区间为空，不建「要不要 X」式提议 UI

- 状态：已裁决（TF-0091）
- 日期：2026-08-31
- 相关：[`0008-structure-from-execution.md`](./0008-structure-from-execution.md) §6（阈值模型）· `packages/workbench/scripts/measure-ask-costs.ts`（测量脚本）· TF-0098（回退 + diff 主安全网）

## 背景

ADR-0008 §6 写下决策规则：

```
p <  K/B          → 沉默
K/B ≤ p ≤ 1−K/C   → 提议
p >  1−K/C        → 直接做
```

**当 `K(1/B + 1/C) > 1` 时提议区间为空**——不存在任何 p 使询问最优。ADR-0008 的后果清单明确留了两笔债：「廉价撤销的系数从未被测量」与「Horvitz 的十二原则与 p* 推导是框架，未被测量」。TF-0091 就是来还这笔债的：**实测 B / C / K，并给出『建 / 不建提议 UI』的裁定。**

## 实测（本机真实 IO，`measure-ask-costs.ts`）

| 量 | 含义 | 实测中位数 |
| --- | --- | --- |
| B_goal | 一次『晋升』（创建 goal，写一个 YAML） | **3ms** |
| C_goal | 一次『拆除』（删一个 goal YAML） | **12ms** |
| C_worktree | 一次重路径拆除（`git worktree remove`） | **1.30s** |

K（问一句的成本）无法机械实测——它是人的读题 + 决策 + 点击 + 打断后的重新聚焦。文献下限约 **2s**（机械往返），含注意力残留可达 **30s**。

## 分析

### 1. 机械成本下，区间必然为空

对 K=2s、B=3ms、C=12ms：`K(1/B + 1/C) ≈ 865 ≫ 1`。任意认知倍率（×3、×5）都改变不了量级——**只要 B、C 是机器级操作，提问永远次优**。

### 2. 关键不等式：C ≤ K ⟹ 区间为空

```
区间非空 ⇔ K/B ≤ 1−K/C
而 K/B > 0 恒成立
若 C ≤ K，则 1−K/C ≤ 0，区间必然为空
```

**如果拆掉一个不想要的工作区比问一句还便宜，就永远不该问——直接做，反正拆得起。** C 是唯一能靠设计控制的项（ADR-0008 已指出），而设计目标只有一个：**让 C 小于 K**。

### 3. 含认知成本的估计下，结论不变

- B（事后补结构）：用户要重开上下文、回忆、归类——**30s ~ 5min**（Giornata 佐证：14.8% 永久无标签，用户主动回避补结构，说明心理成本高）。
- C（设计后的拆除）：一次撤销——**1 ~ 5s**。
- K：**2 ~ 10s**。

`K(1/B + 1/C) = 5×(1/30 + 1/3) ≈ 1.8 > 1`。即使用最宽松的 B=60s、C=1s、K=2s：`2×(1/60 + 1) ≈ 2.03 > 1`。**区间为空不是边界情况，是常态。**

### 4. p* 的裁定含义

验收要求「得出 p* = C/(B+C) 的具体数值」。数学上 p* 是 K→0 时提议区间的对称点；**实测表明区间为空时 p* 无决策意义**——正确结论是落在规则右端：**永远直接做**（p > 1−K/C 恒成立，因为 1−K/C < 0）。C/(B+C) 只在未来设计把 C 抬到 ≥K 时才重新计算。

## 决策

1. **不建「要不要 X」式提议 UI。** 所有「要不要把它变成一个任务 / 工作区 / 计划？」式确认提示一律删除，选一边站——**站『直接做』**。
2. **替代机制是廉价可逆，不是询问。** 「直接做」成立的前提是 C 被设计到 < K：拆除必须是**一次撤销、秒级、无残留**。承载物是 TF-0098（回退 + diff 作为主安全网，三个动作分别标注），其定位从「L2 的一个机制」升级为**提议 UI 的正式替代品**。
3. **C 的设计预算写死**：任何可提议的产物，其拆除路径成本必须 ≤ 一次撤销 ≤ 提问成本（K）。超出预算的产物类型（如 worktree，1.30s 且需清理）**禁止被系统自动创建**——自动创建的只能是撤销级产物。
4. **加法式输出不受影响。** 本裁定只杀死「询问要不要」的确认步骤，不杀死「直接产出 + 备选留在一键外」的加法式呈现（TF-0094 生成 N 个展示 1 个、TF-0095 默认折叠的决策账本）——它们没有「请选择」界面，不经过 p 决策，与本裁定正交。
5. **测量脚本保留**（`measure-ask-costs.ts`），参数变化时重跑即可复核。

## 后果

**正面**

- 砍掉一整类 UI（确认对话框），符合 L0（线性对话零改动）与 L2（加法式、零仪式）。
- 「直接做 + 廉价撤销」与 Gilbert & Ebert 一致：人偏好可逆决定（66.3%），用「工作区一旦进入就感觉是定下来的」换接受度。
- 验证了 TF-0106 风险的判断：多数「要不要变成任务」式提示不通过检验，此风险转 done。

**负面 / 风险**

- **依赖撤销的可靠性**：廉价撤销必须真便宜、真可靠，否则退回「问一句」是唯一保底。TF-0098 因此从可选升级为必需。
- **C < K 是可被违反的设计约束**：任何新增产物类型都必须过「拆除 ≤ 一次撤销」这条预算，需要把它写进后续任务的验收。
- **K 未实测**：本文用文献区间估计（2–30s），未做真人打断实验。区间结论对 K 单调不利（K 越大区间越空），所以不改变裁定方向。

# ADR-0022：声明的状态语义——done 必须有读数，覆盖读数与单次观测分开标

- 状态：已接受（2026-09-26，第四轮阶段 B 的决策节点 TF-0278）
- 相关：[ADR-0020](0020-relay-handoff-upload-surface.md)（上传面）、[ADR-0021](0021-retire-all-ci-channels.md)（CI 退役后读数只剩本机）、TF-0274（证据账本与失效门禁）

## 背景

第四轮建立了证据账本：每条声明点名仪器、覆盖路径、读数形状，仪器或被测路径一变读数即失效。
但账本只解决了「有读数怎么存」，没解决**「没读数的 done 算什么」**：

- 森林 271 个节点里，47 个 `done` 的 `evidence` 为空（全是 TF-0001…TF-0116 的 MVP 骨架期）；
- 它们的交付物大多**仍在**（`packages/workbench/src/scheduler`、`src/automaton`、`src/types` …），
  而且被 workbench 套件覆盖（该套件有有效读数 1004 pass / 0 fail；2026-09-26 收尾重取为 1014 pass / 0 fail）；
- 但**套件绿不等于这个节点的原始验收被复算过**——它只证明「交付物存在且被测」。
- 另一类更糟：`done` 的**仪器已经不存在了**（例如 TF-0103「修复 ci.yml 的 15 处 tab 缩进」，
  而 `.gitlab-ci.yml` 已随 ADR-0021 删除）。

于是「done」在这批节点上意味着「有人说过」，而这正是 TF-0253 那条风险说的状态假阳性。

## 决策

### 1. `done` 必须指向读数，且读数分两级

| 级别 | 含义 | 允许 |
| --- | --- | --- |
| **直接读数** | 注册的读数，其仪器**实际执行了**该节点的交付物（例如该模块的测试、该命令的门禁） | 任意节点 |
| **覆盖读数** | 注册的读数，其 `subject_paths` 覆盖该节点的交付物路径，但仪器**没有**复算该节点的原始验收 | 仅历史节点，且 evidence 必须写明「间接」 |

覆盖读数不是降级借口：它必须点名 claim id 与路径，并显式声明「这不是本节点原始验收的直接
复算」。写不出这句话的，就不是覆盖读数。

### 2. 没有读数就没有 done

- 交付物在、但没有任何读数覆盖它 → **`review_needed`**（landed-unknown：代码在，没人量过）。
- 交付物已不存在（其主体被删除或被后续决策取代）→ **`deprecated`**。
- 森林 CLI 的合法状态集里已有 `review_needed`，不新增状态值——新增状态会让
  `validate` / `check-landing` 与既有导出物全部要改，而 `review_needed` 的语义正好是
  「需要人看一眼」，与 landed-unknown 一致。

### 3. 仪器退役的读数只能当观测

L3（仪器已不存在）**不能**充当 `done` 的证据。它记成 `observation`，且相关声明必须写成
「某时某环境观测到 X」，并写明仪器已退役、不可重算。这条直接承接 ADR-0021 的代价：
CI 退役使既有流水线读数不可复核，它们从此只能是观测。

### 4. `done` 不因读数的自然失效而回退

读数 stale（代码改了）**不等于**节点没完成——它意味着**需要重取读数**。门禁报红是要人
重跑仪器，不是把节点改回未完成。状态回退只由「交付物消失」或「验收被推翻」触发。

## 代价

1. **47 个历史节点要逐条定性**（TF-0279），不能批量改状态——批量改等于把「有人说过」换成
   「工具说过」，性质没变。
2. **覆盖读数是弱证据**，会被误读成直接证据。因此措辞是强制的一部分：evidence 里必须出现
   「间接」与 claim id。
3. **`review_needed` 会变多**，森林的「未完成」读数会上升。这是**如实**上升，不是退步。

## 复核（触发重估的条件）

- 如果某个 `review_needed` 节点后来有了直接读数，改回 `done` 并写读数 id。
- 如果覆盖读数的路径映射被证明是错的（模块换了、交付物其实在别处），该节点的定性要重做。
- 若未来 CI 或第二台机器重新成为通道，L3 观测可以被升级为 L1/L2 读数——届时按新读数重判。

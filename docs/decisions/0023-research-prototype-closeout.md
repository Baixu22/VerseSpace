# ADR-0023：按工程研究原型收尾，固定声明与通道边界

- 状态：已接受（2026-09-26，用户要求按前一轮探索结论完成收尾）
- 补充 ADR-0010、ADR-0019、ADR-0022；取代 ADR-0017 关于 Codex 审批始终不咨询封印的现行描述。

## 交付边界

本轮交付面向个人开发者的本地工程研究原型：记录可观测的文件读取前提，在变化后给出可追溯提示与恢复信息。闭环指源码、可执行检查、明确限制和可复核记录一致，不代表已证实生产率提升，也不代表所有工具调用或写者均可观测。
保持线性对话、CLI、同一文件账本、MCP 只读投影与恢复卡。冻结功能扩展；真人收益研究、非 Windows 执行验证和公开发行是独立后续工作，不作为本次原型结题条件。旧发行物不继承当前源码读数。研究贡献是系统组合与边界经验，不宣称算法首创。

## Codex 的当前能力

Codex 是实验通道。生产路径已在可归因的写审批上调用封印，但这不是完整写保护：CLI 可能不发审批；目标可能无法归因；读取可能没有结构化路径；封印故障时当前实现放行。缺少前提不能解释为前提有效。
结构化 read/listFiles 路径及有限 cat 后备解析可产生足迹；无结构化路径的 Get-Content 不在当前后备解析范围内。对某个命令的负面观测不能泛化到整个 CLI 版本。界面和包说明显式标注此限制，不新增通用 Shell 解析器。
真实实验采用 own-fresh / own-stale：先让车道自己读，再捕获该写者的前提。无目标读取足迹、未能建立所需失效状态、模型回合失败均返回无法测量（exit 2）。对照冻结写回合前的同一写者和同一组前提；封印事件只统计写回合，输出判决内容。exit 0 只说明观测完成，需结合 fresh 对照、是否复读、写入与阻断事件判断因果。

## 声明账本

当前证据必须有实际执行退出码、被测提交、符合类型的读数，以及声明规定的期望值和下限；仪器非零退出、零测试冒充通过、跨包输入变化均不能保持有效。记录器必须执行仪器。它不是防篡改签名系统：计数仍需与原始输出核对，valid 只针对注册的命题和依赖范围。
原 claim-codex-write-unsealed 记录的是 ff6ac4ab 时刻的旧实验；此后审批接线与实验定义均已变化。将其明确记为 L3 历史观测，保留原读数和摘要，不为它重造当前读数，不用于当前 done 的证据。L3 即使旧仪器消失也只计 observation，必须说明退役原因。

## 上传面引用裁决

六条 `referenced-but-local` 按 ADR-0020「复核」一节逐条裁决：六份材料维持本机——原始 dump 换机不可复算，定位原稿与按日期报告属过程证据，其结论已由[收尾记录](../handoff/2026-09-26-research-closeout.md)接管；fit 账本与设计提示词里的承重引用改为指向收尾记录。
唯一剩下的引用方是 2026-09-25 那份交接记录 §5 的「待裁决」表格本身。该表记录的就是这次裁决，读者在同一张表里被告知材料留本机，所以它不是换机会跟空的指针。这一条例外写进 `scripts/upload-surface/policy.json` 的 `acceptedLocalReferences`：逐条具名、带理由、精确匹配引用方与被引方（不用 glob，新的死指针无法继承旧决定）。`node scripts/check-upload-surface.mjs --strict-references` 因此 exit 0，例外仍在输出里逐条列出，不被静默吞掉。
已知盲区：门禁按「已入库文档是否包含本机文档路径」的子串判定，ADR 里 `../positioning-v5.md` 这类相对写法不在覆盖范围内。本轮不改判定逻辑——那会把已接受的 ADR 拉进重写；盲区记在这里，不读作「引用关系已全部核对」。2026-09-26 第二轮实测又扩了一条：它同样测不到**指向已存在文件的错误相对深度**——阶段 A+B 交接报告移入 `docs/handoff/` 后 24 条链接全部指错目录，门禁照样 exit 0。判断链接完整性必须另跑一次解析，不能把这个门禁当链接检查器。

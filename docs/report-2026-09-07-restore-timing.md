# TF-0126 恢复耗时观测

> 本文保留最初计量节点的验证记录；后续开发与最新结果见 [主线验收记录](./report-2026-09-07-mainline.md)。

2026-09-07：补齐阶段 B「恢复到首条消息的中位间隔不因卡片上升超过 20%」的测量链路。代码已完成，效果验收仍等待带有观测字段的对照样本。

UI 加载目标线程后，沿用 `thread.restored` 记录 `resumeCardVisible` 与 `lastMessageId`。前者与卡片初始呈现条件一致，后者标记本次加载的消息边界；旧客户端可省略，统计不据此猜测卡片状态或首条消息。

`workbench stats --json` 的 `lifecycle.restoreToMessage` 返回近七天有卡、无卡、卡片状态未知三组样本数与中位毫秒数，以及未配对次数、中位数相对差异和是否超过 20%。终端输出与 fit 账本使用同一份结果。

- 只配对加载边界之后的第一条用户消息，助手回复不计。
- 切换、再次恢复或离开当前线程会关闭这次窗口，之后的消息不借给上一次恢复。
- 观测晚于首条消息、时间无效、历史边界被删除或尚未发消息时，保留未配对计数。
- 缺少对照组或无卡中位数为零时，差异与 20% 判定均为 `null`，输出 `unknown`。
- 这是观察性比较，不证明因果，也不自动折叠卡片、修改 fit 或关闭节点。真实时长使用服务端恢复事件与消息时间戳；过晚到达的观测会被排除。

验证：Workbench 全套 547 pass / 0 fail（含现有真进程 E2E）；UI 11 pass / 0 fail；两处 typecheck、变更文件 Biome、UI 构建均通过。新增覆盖分组、中位数、窗口边界、旧记录、延迟观测、输入校验、HTTP 落库和 UI 过时请求。构建仍有既有的 500 kB chunk 提示。

本仓库当前实测仍为 0 线程，两组有效样本均为 0，比较结果为 `unknown`。测试夹具不计入使用样本。TF-0126 保持进行中；TF-0133 的通知比例开工条件保持原样。

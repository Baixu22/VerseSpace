## 2. 四种事实的口径

| 事实 | 签发者 | 明确不能证明 |
| --- | --- | --- |
| Observed input | 工具调用 + 采集时刻版本（`footprint.ts`） | 采集版本 ≠ 工具实际返回内容；大文件只有 size；目录/截断/未归因命令为未知 |
| Declared origin | 调用者显式写的 `artifact.inputs` | 不是因果，结构与先读后写只算候选 |
| Verified artifact | 一次声明范围检查的真实退出与报告（`status.ts`） | 不证明语义正确，不覆盖未声明输入，不跨工位继承 |
| Target applicability | 目标 ref 的 commit/tree 与输入 blob 比对（`snapshot.ts`） | 只说目标上输入字节相同，不说合并结果已检查 |

消费边界：只覆盖 Workbench 管理的验收消费；裸编辑器、Git 直接操作、无审批写入不在保证内。
ADR-0023 的实验性 Codex 通道与 ADR-0024 的退役范围保持不变。

## 3. 顺带修掉的一个真实缺陷

`node scripts/check-upload-surface.mjs --strict-references` 在本机报 1 条 `unclassified`
违规，路径是一个真实存在的本机草稿文件，却被写成带引号的转义形式。原因是
`git ls-files` 默认对非 ASCII 路径做 C 风格转义（`core.quotepath`），门禁拿到的是
`".agent-contexts/…/…md"`，任何 policy 规则都匹配不到。门禁因此把「策略已经覆盖的目录」
报成「策略没覆盖」。

修法是给每次列表查询加 `-c core.quotepath=false`，而不是在门禁里重新实现 git 的转义规则。
这个缺陷与 ADR-0026 无关，但它是本轮门禁的阻塞项，且属于同一类「读数看起来是红/绿，其实
量错了对象」的问题，所以单独一个提交，不混进 ADR 提交。

## 5. 刻意没做什么

- **没有开工阶段二的实现节点**。TF-0285/0286 仍是 `proposed`；是否动手由独立 judge 与冻结场景裁决，
  不因任务已列出而自动扩展。
- **没有把 Observed input 升级成「工具返回内容凭据」**。ADR 里明确写了当前 `version` 是采集时刻的
  采样版本，问题留给 TF-0289/0290，不在文档里先宣布解决。
- **没有顺手重排既有 ADR**，也没有把 `docs/decisions/README.md` 的表格格式统一——那会把一个
  范围决策变成格式大改。
- **没有为了绿而改 claims 期望值**。

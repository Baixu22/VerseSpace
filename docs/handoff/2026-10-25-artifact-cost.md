# TF-0307：产物证据的时间、空间与重复检查成本

本节点在 Windows 本机串行量测产物证据链路，使用真实 Git/Node 临时工位、固定文件
检查和合成 JSONL ledger。冻结计划为 1 次预热 + 5 个新鲜热样本、四次内容不变的
消费、单样本 60 秒上限，并覆盖 1k/10k/50k 三档 ledger。计划摘要为
`74d54253d768ff5074aa3e837c670c55be2ce70d578a477904acc18ab2f662ff`，冻结 runner、
fixture、统计器、强朴素检查器和 `check.cjs` 共五个观察器摘要。

首次试跑在固定文件 checkpoint 仍带任意 `command` 时被 Verifier 判为
`needs_human`；该次没有形成读数。删除冲突字段后重新执行 typecheck、统计测试并
重冻观察器；计划、组定义、样本数、预算和裁决规则均未改变。完整初始失败保留本机。

这里的 cold 是 setup 后的第一次受测调用，不是清空 OS 文件缓存；hot 是随后五个
独立样本或重复调用的最近秩 median/p95。固定检查对象中的 `runMs` 与 `copyMs`
分开记录。合成日志尺度只说明已测工作量，不是容量保证。

## 四次消费对照

强朴素检查器不读取 ledger，因此只量一轮；同一 5 样本分布与三个 Workbench 尺度
比较。每次增强样本真实执行一次固定副本检查和四次 run lock 内消费门；全部 4 次
均返回可用，review 为 current，验证请求为 1。强朴素每次消费重跑检查，共 4 次。

| ledger 行数 | 增强 cold ms | 增强 median / p95 ms | 朴素 median / p95 ms | 检查次数 | 裁决 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1,000 | 4803.472 | 5092.126 / 5934.099 | 238.779 / 300.984 | 1 / 4 | no-net-time-benefit |
| 10,000 | 5337.592 | 8467.101 / 9500.772 | 238.779 / 300.984 | 1 / 4 | no-net-time-benefit |
| 50,000 | 9725.550 | 6573.739 / 7473.914 | 238.779 / 300.984 | 1 / 4 | no-net-time-benefit |

冻结规则要求增强 median 更低且五值与朴素五值完全分离才能记录时间优势。三个
尺度都不满足，因此结论是 **保留低成本策略 / 不宣称总体加速**。增强确实把四次
消费中的检查次数降到一次；这是调用次数与不必要重验的收益，不足以抵消当前增强
链路的总成本。

## 裁决与边界

- 三次固定检查、18 个增强样本和 18 个后置消费门均安全可用；`budgetExceeded` 与
  `safetyViolations` 都是空数组。
- 四次消费只发出一次验证请求，但当前固定副本、状态投影和四次 guard 查询的总时间
  在三个尺度均高于朴素重跑四次的分布，故停止扩展性能声明。
- 没有调用模型，token/cost 保持 `null`；没有真人、市场、跨机容量或自然工作流收益。
- 原始 JSON、逐样本值、内存观测与失败现场留 `evidence/raw/`，不进入上传面。

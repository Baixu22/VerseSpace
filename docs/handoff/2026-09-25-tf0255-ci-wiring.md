## 0. 结论摘要

TF-0255 的四条验收里只剩第 2 条（「CI 在隔离 workspace 中运行浏览器 suite」）。
上一轮拒绝草拟它的理由很具体：**草稿会变成无人验证的假接线**。
本轮的做法是把这条理由消掉——先把命令序列做成一个能跑的脚本并实测，
再让 CI job 只做薄包装：

| 产物 | 内容 |
| --- | --- |
| `scripts/win/e2e-browser.ps1` | 一条命令跑完整条序列（建工作区 → 起服务 → 播前置数据 → Playwright → 拆干净） |
| `.gitlab-ci.yml` 的 `workbench-ui-e2e` job | 三行：`extends` / `resource_group` / `script: ./scripts/win/e2e-browser.ps1` |
| `vite.config.ts` | 端口与代理目标可配（固定 7700/5188 会和开发者已在跑的实例打架） |
| `dropdown.spec.ts` | opt-in 用例收尾复原 `effort`，让它可重复跑（§3） |

**本机读数**：脚本 exit 0、**14 passed / 0 skipped / 0 failed**；同一工作区连跑两次都过。

**没做的一件事**：没有 push，所以 job 在 JihuLab 上还没跑过。第 2 条**要等流水线绿了才算达成**。

## 1. 脚本做了什么

```
1. 建临时隔离工作区，在里面 `workbench init`
2. 配置 opt-in 车道（provider=openai-responses, effort=high）
3. 起后端（-ApiPort）与 Vite（-UiPort）——两个端口都可移
4. 等两个服务就绪（HTTP 有应答即算起来，401 也算）
5. 用 /api/bootstrap 拿 token，POST 两个会话——**这就是 spec 的前置数据**
6. 跑 playwright test（exit code 原样透出）
7. finally：taskkill /T 杀进程树 → 删临时工作区（-KeepWorkspace 可保留现场与日志）
```

**为什么是脚本而不是把这一坨写进 YAML**：写进 YAML 的话，本机没有任何东西在执行它，
它就只能靠"读起来像对"来验收。现在 YAML 里只有一行调用，而那一行调用的东西刚刚在本机跑过。

## 2. 为「可重复」做的两处改动

### 2.1 端口可移（`apps/workbench-ui/vite.config.ts`）

```ts
port: Number(process.env.WORKBENCH_UI_DEV_PORT ?? 5188),
proxy: { "/api": process.env.WORKBENCH_API_TARGET ?? "http://127.0.0.1:7700" },
```

默认值不变。没有这一步，脚本只能用固定的 7700/5188——而开发机上那两个端口
很可能正被另一个 `workbench ui` / `vite` 占着，CI 和本机开发会互相踩。

### 2.2 前置数据由脚本播，而不是靠运气

`ui.spec.ts` 的两条用例现在**要求**前置数据（上一轮改成 fail with reason）。
脚本负责把它们造出来（两个会话），所以默认运行是 14 passed / 0 skipped——
而不是"本机恰好有会话所以过了"。

## 3. opt-in 车道的状态性：RED / GREEN

`dropdown.spec.ts:76` 的前置条件是**工作区已经配成 `effort: high`**，
而它的断言会把这个条件消费掉（最后一步把推理力度改回「默认」并断言持久化）。

| 阶段 | 读数 |
| --- | --- |
| **RED**（修复前，实测 2026-09-25） | 同一工作区第二次跑 → `推理力度` 读到「默认」而非「高」→ **1 failed** |
| **GREEN**（修复后） | 同一工作区**连跑两次** → 两次都 **14 passed** |

修法只有一行，加在断言之后：把 `effort` 复原成 `high`，并注明「只撤销断言造成的副作用」。
断言本身一个字没改。

这条也解释了为什么脚本每次给**新**工作区——那是更干净的契约，但用例不该依赖调用方守规矩。

## 4. CI job

```yaml
workbench-ui-e2e:
  extends: .bun-setup
  stage: verify
  timeout: 25m
  resource_group: heavy
  rules:
    - if: $CI_PIPELINE_SOURCE == "web"
    - changes: !reference [.paths, workbench_ui_e2e]
  script:
    - ./scripts/win/e2e-browser.ps1
```

| 决定 | 理由 |
| --- | --- |
| `resource_group: heavy` | 它起 Vite dev server + Chromium，和 UI 套件同级的重活；`concurrent = 4` 而机器 16 GB |
| **不装浏览器** | 自托管 runner 就是这台机器，`%LOCALAPPDATA%\ms-playwright` 里已有 Chromium。换用户跑时给脚本加 `-InstallBrowsers`（注释里写了） |
| 不需要模型凭据 | opt-in 用例只验证设置 API 的持久化，**不调 provider**——所以 CI 不需要 `E2E_LLM_KEY` |
| paths 过滤含 `packages/workbench/src/**` | spec 在 `apps/` 下，但它驱动的是真后端；后端变了也该跑 |

## 6. 刻意没做

| 没做 | 为什么 |
| --- | --- |
| **不 push / 不触发流水线** | 远程动作，需要维护者拍板；而且这正是"第 2 条算不算达成"的分界线，不该由我宣布 |
| **不装浏览器** | 见 §4；这台机器已有缓存，多一步下载只增加失败面 |
| **不把 opt-in 用例改成默认** | 它需要一个专门配置的工作区，属于测试环境搭建 |
| **不声称 CI 绿** | 本报告只声明"命令序列在本机通过" |
